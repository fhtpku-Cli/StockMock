## 实现与接口

扩展 `/api/portfolio`，在同一账户状态、有效报价和汇率批次中返回持仓人民币市值、成本、浮动收益率、比例、行情时间，以及现金／持仓／应收构成和市场／交易币种分组。现金包含占用，不重复计入；金额用Decimal计算并按人民币分显示，各明细显示金额之和等于构成总额。总额缺失或非正时比例为null；汇率缺失不抹去有效原币值。采集前后校验账户变化，最多三次采集，仍变化返回409 `valuation_changed`。拆股后报价、新鲜度和原有来源校验保留。

增加 `/api/ledger/page`、`/api/cash-statement`、`/api/ledger/export.csv`，归档路径分别为 `/api/rounds/{round_id}/ledger`、`cash-statement`、`ledger/export.csv`。流水默认50条、最大100条，以当前轮次追加条数 `boundary` 保证旧页稳定；下一页沿用边界，新追加项在刷新后出现。归档流水保留原 `items,total,offset,limit`，新增 `boundary,round_id`。前端切换轮次须重载。核对始终使用当次完整状态，`boundary` 不截断核对，类型筛选只影响列表和 `selected_net_change`。导出忽略分页及边界，覆盖当次完整匹配记录。

日期参数按确认时间转换北京时间后比较，等价于含开始日00:00、排他结束日次日00:00。全类型期初／期末不会随类型筛选变化。不补造本金流水，不推断旧换汇或公司行动关联，不自动修复差额。未知类型和零额记录保留。旧全量数组和完整CSV接口继续工作；原CSV自由文本保护也覆盖编号、未知类型和委托编号，负金额保持数值。

增加 `/api/snapshots/range`、`/api/snapshots/export.csv` 及归档同构路径，旧快照数组不变。`range=all|7d|30d|90d|custom`，快捷日期以当前北京日期或归档日期为结束日。首末是实际记录，可为missing/stale；不跳过无效端点。只在不同日完整首末记录间计算差额，内部缺口明确提示。CSV只输出已保存值，缺失金额空白。

`/api/health` 保留原撮合worker字段，增加 `plan_worker.last_run/status`，用于部署后分别核实两项后台任务。没有引入新监控服务或持久统计表。所有新查询沿用现有鉴权。

最小字段说明见 `.omo/evidence/0.3.0/backend-api.md`。新增响应字段为可选默认值的持仓／资产字段，旧持久JSON结构未修改，原金额、流水和历史快照不迁移重算。

## 集成修复：百分比普通十进制序列化

前端真实浏览器在归档并重置为纯现金轮次后发现 `positions_percent="0E+2"` 被严格十进制字符串规则拒绝，导致资产页加载失败。后端随后用真实HTTP在临时SQLite重现三种场景：纯现金零占比、极小非零占比与收益率、零收益率。修复前专用回归3项均失败，保存原响应于 `backend/serialization-before/percentage-*.json`，日志 `backend/serialization-before.log`。

根因是Pydantic默认Decimal JSON输出允许指数形式，现有前端金额语法只接受普通十进制。修复只在新增百分比字段的JSON边界使用共享 `PlainSerializer` 与 `format(value, 'f')`；内部仍为原Decimal，未量化、舍入、转float或修改账本。适用持仓收益率与权重、三项构成比例、市场和币种分组比例。

实际HTTP结果：纯现金 `0E+2` 变为 `0`；极小权重 `9.999999900000000999999990000E-7` 变为 `0.0000009999999900000000999999990000`；微小收益率 `1.000000000010000000000100000E-9` 变为 `0.000000001000000000010000000000100000`，数值精确相等且不归零。三场景均断言分析前后State完全相同。

复跑命令：在backend执行 `STOCKMOCK_EVIDENCE="$PWD/../.omo/evidence/0.3.0/backend/serialization-after" uv run pytest tests/test_analysis_serialization.py -q`，结果3 passed，证据为 `serialization-after.log` 与 `serialization-after/percentage-*.json`。随后全套339 passed、basedpyright无错误、Ruff检查及格式检查全通过；日志沿用上表路径。候选服务需重启加载修复，前端浏览器复验由前端成员继续记录。本轮没有修改版本、正式账户或部署。
