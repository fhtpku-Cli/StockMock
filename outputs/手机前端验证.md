# 手机前端验证

本轮已完成手机界面与主屏幕入口修复，浏览器验证通过；尚未进行实际 iPhone Safari 验收。真实服务仅登录与读取，没有新增个人交易、公司行动或重开轮次。所有截图及账户响应保存在忽略提交的 `.omo/evidence/mobile-ui/`，不公开发布。

## 修复内容

补充 `viewport-fit=cover`、安全区留白、Apple 主屏幕元数据及本地 180/192/512 PNG 图标。手机输入字号为 16px，分段按钮与标的链接至少 44px；横屏触控设备也使用手机导航。弹窗跟随 VisualViewport 的高度与偏移，短视口内可滚动到交易按钮。

401 响应使账户弹窗关闭、清除当前账户查询缓存并返回明确的过期登录页。联网恢复会重新获取查询；离线及页面重新可见时使交易预览失效，需要重新预览。网络回执丢失时保持原请求标识，重试不产生重复订单。未增加 Service Worker 或离线账户缓存，首次离线打开不保证可用。

## 工具限制与最终手机交接

本机 `bun test` 及显式 `bun test tests/*.test.ts` 均停留在版本输出，未完成测试用例，已终止；该目录下本次运行不计为单测通过，原始输出在 `unit.log`。PM 随后将相同前端源码、测试及 node_modules 复制到隔离临时目录，实际完成 6 个测试、19 个断言；原目录卡在 openat 的原因尚未确定，不能归因于系统权限。最新回执修复后的最终单测由 PM 更新临时副本后复验。默认构建入口也曾停滞，实际使用 Node 加 Vite native 配置加载器完成构建，无依赖或生产配置降级。构建仅出现上游 Zod 注释处理警告。

当前结论是浏览器候选版可交给 PM 集成。短视口测试不等于真实软键盘，Chromium iPhone 尺寸不等于 Safari。最终只需一次实际 iPhone 检查：通过 PM 配置的私人 HTTPS 地址登录，添加到主屏幕，检查图标、刘海与底部安全区；打开交易弹窗输入数字并滚动，再切换网络确认重新预览。无需为了验收在个人账户提交真实模拟委托。电脑服务持续运行与私人 HTTPS 连通性由 PM 的接入验收负责。

## 独立评审修复：切回前台后的未确认委托

评审复现了近满仓委托已受理但回执丢失后，切回前台清空预览，再预览因原订单已占用资金而显示资金不足。现保存首次提交的完整内容与请求编号；结果未确认时锁定编辑，联网后通过“重试确认委托结果”调用原幂等下单接口，不经过新预览、不生成新编号。API 错误保留 HTTP 状态，明确的 4xx 拒绝（408 超时除外）解除待确认状态，要求重新预览；网络或 5xx 错误保留核对入口。

针对性验证使用 `node tests/mobile.mjs` 和隔离 8001 后端，数量改为 9900、限价 100；服务器受理后主动丢弃回执，触发可见事件，再断网及恢复，确认编辑锁定、离线核对按钮禁用、恢复后不出现重新预览入口。两次 POST 的完整内容相同，此时只有 1 笔订单；同账户桌面读取、撤单、过期后登录仍通过。另用真实 API 并发占用资金：先预览 100 股，再从另一请求受理 9900 股，前端提交收到真实 4xx 后恢复编辑与预览入口。

实际输出在 `.omo/evidence/mobile-ui/reconciliation-run.log`，更新的 `controlled.json` 包含 12 个视图、0 页面错误及两个 axe 页面 0 违规。报告分别标明前两次核对请求和后一次明确拒绝；仅统计核对阶段的持久订单数，不将随后并发验收订单混入该断言。类型检查和重建退出码 0，构建输出见 `reconciliation-build.log`。未操作真实个人交易，受控临时服务验证后停止。

独立评审另外重跑了回执恢复、真实并发 4xx 解锁及后续 401 清理，均通过；私有证据 `.omo/evidence/phone-review/browser-fixed.json`。
