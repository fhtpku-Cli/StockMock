## 产品与接口决定

### D1　独立只读时段查询

新增认证`GET /api/markets/{market}/session`，只接受`CN|HK|US`，非法市场422、未登录401。沿用`market_routes.py`注册及`auth.require`；纯投影放新`market_session.py`，响应类型放`market_session_models.py`。单次取得`datetime.now(UTC)`并传入投影，不允许请求自定now；不调用证券lookup、Discovery、Provider、Store或交易受理。响应`Cache-Control: no-store`，仅沿用既有日历实例缓存，不增加投影缓存或外部依赖。

独立按市场查询，使报价失败不遮蔽时段，也避免为展示触发证券发现网络及持久副作用。市场时间来自服务端；响应不能用于控制原买卖按钮或更改订单参数。

| 字段 | 语义 |
| --- | --- |
| `market` | `CN\|HK\|US`，与请求一致 |
| `as_of` | 本次服务端查询时刻，带时区ISO时间 |
| `market_timezone` | 与市场对应的`Asia/Shanghai\|Asia/Hong_Kong\|America/New_York` |
| `market_date` | as_of换算交易所时区后的YYYY-MM-DD |
| `phase` | `supported\|before_open\|break\|unsupported_closing\|after_hours\|non_session_day\|unknown` |
| `current_period` | 仅supported为`{start,end}`，满足`start <= as_of < end`；其他为null |
| `next_period` | 能确定时为严格在as_of之后开始的首个支持区间`{start,end}`；无法确定为null。上午supported返回下午，下午supported返回下一交易日第一段，不返回当前段开盘 |
| `reason` | phase未知时固定`calendar_unavailable`，其余为null；unknown的两个period均null |

区间均为带时区ISO时间且start<end。当前时段能确定但下一段超出日历范围或计算失败时，保留已知phase/current_period，next_period=null，页面明确“下一支持时段暂不可用”；不因缺少未来日历抹掉已知当前事实。若连查询日或当前日历结构也无法确定，则整体unknown。前后端校验枚举、市场/时区/日期匹配、空值组合、区间顺序及与as_of关系；同一瞬间不同偏移合法，额外字段可忽略。不增加冻结contract或强版本绑定。

### D2　日历口径与状态解释

复用锁定的`exchange_calendars`4.13.2及既有calendar实例，按交易所时区取当日，读取session_open/close/break_start/break_end。CN支持截止是日历close减3分钟，HK/US使用当日实际日历close；半日、夏令时、提前结束取日历值，不硬编码正常收盘。午休两端均NaT表示无午休；不完整或反序结构视为未知。支持区间左闭右开，不按分钟截断now，不修改现有完整成交区间的闭区间截止规则。

| phase | 页面文案与关系 |
| --- | --- |
| supported | “支持时段内（按日历）”，展示本段结束时间 |
| before_open | “尚未进入今日支持时段”，next为今日第一段 |
| break | “午间休息（按日历）”，next为当日下午段，不能用window返回的上午开盘 |
| unsupported_closing | CN支持截止至实际日历close之间：“收盘阶段，本应用不支持”；正常日14:57–15:00不能称已收盘，next为下一交易日第一段 |
| after_hours | 从实际日历close起：“今日支持时段已结束”；不声称交易所所有交易阶段均已结束 |
| non_session_day | “非交易日（按日历）”；不根据周一至周五推断，next为下一日历交易日第一段 |
| unknown | “市场时段暂不可用”；无区间，提供重试，不假装休市 |

已知next展示“下一支持时段 YYYY-MM-DD HH:mm:ss 至 YYYY-MM-DD HH:mm:ss（北京时间）”；未知next明确提示暂不可用。固定解释：“仅按交易日历说明本应用支持时段，不代表实时停市或个股停牌状态。限价单可预挂；市价模拟仅在支持时段受理，仍需通过证券资格、行情、资金等检查。”CN收盘阶段补充预挂单仍须等待参考日实际收盘并取得合格日线；HK保留原“仅观察”，不暗示开放港股交易。

日历异常在新展示边界转为对应未知并保留安全错误类别，不暴露异常栈；不扩大日历覆盖、猜测工作日或换来源以消除未知。当前依赖XSHG覆盖止于2026-12-31；这属于日历可用性限制，不能把未来推导称为交易所实时证明。

### D3　刷新、失败与旧服务

时段区放在详情身份/资格之后、报价条件分支之外，标题“查询时市场时段”，显示as_of完整年月日秒及北京时间。报价时间继续单列，不改全站时间格式。说明前台停留约每30秒更新，不增加倒计时、客户端时钟推导或秒级轮询。

采用既有React Query，queryKey至少含market，消费AbortSignal；详情打开/重开强制查询，局部30秒轮询、后台不轮询，在线恢复/聚焦刷新，接入全局invalidateQueries并提供“刷新市场时段”按钮。现有staleTime不是轮询，不能称已有自动更新。初次/重开/切换或正在刷新显示查询中，不把旧缓存当本次成功；成功始终注明as_of，下一响应前不自行改phase。

离线、HTTP/schema错误、未知phase、字段矛盾或旧服务404，只在时段区显示暂不可用及重试/联网提示，隐藏旧phase/next；失效登录沿用401行为。新前端兼容旧服务的局部404，旧前端无需新接口；不承诺旧可执行程序回退。关闭停止轮询，切证券或同键重刷的晚旧响应不能覆盖新结果；优先使用现有按symbol重挂载、查询键与取消，不造通用请求框架。新字段不得新增按钮禁用条件，原预览/下单校验保持。
