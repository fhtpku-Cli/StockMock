2026-11-19。独立报告审查的是正式线 `13326eb`。本轮候选从 `241c965` 开始，包含此前验收的复盘阅读减负改动 `6097011`。两者相对正式线的产品差异只有默认收起所选委托的“时间与交易计划”。候选独立于采样会话的主目录、账户、服务与行情源。

## 哪些判断成立

| 原报告 | 本轮判断与采用的做法 |
| --- | --- |
| 1 持仓需要横滑 | 成立。按原审查的四持仓样本复现，桌面 679px、手机 308px 的容器都装着 720px 的表。宽容器用完整表，窄容器按证券呈现卡片，一次渲染同一组数据。手机优先展示人民币市值、全账户占比、原币浮盈和收益率，保留单位成本、可卖、占用及下一批解锁信息。 |
| 2 持仓与现金入口过深 | 成立。同样本上，持仓标题原先位于桌面第 1668px、手机第 2249px。可用资金、占用、活动委托与持仓前置，构成和历史分析后置，保留估值状态与需要处理的警示。首页无未读时保留“全部提示”入口。 |
| 3 委托的“写复盘”落在普通笔记 | 成立。直接在委托列表打开该单对应的正式复盘，按准确轮次、计划或旧无计划订单定位，再选中来源委托。关闭回到原列表。保留针对该笔委托写普通笔记的能力。 |
| 4 复盘展开后太长 | 成立。原报告的像素数针对指定样本，不能外推所有计划。复盘详情改用二级面板，提供计划与结果、委托依据、正式结论、事实与笔记四个入口；查证期间保留在写的结论。相同版本可展开六项对照，不同版本可直接比较，缺快照显示缺失。 |
| 5 交易上下文、预览、回执与撤单 | 成立。详情进入交易后可返回该证券，买卖显示有时间和币种的参考信息。预览后直接定位费用与占用。成功显示服务器返回的委托回执，等待成交与已成交仍分别表达。站内撤单确认保留延迟期间可能成交、申请不可撤回等提示。 |
| 6 手机小字与小按钮 | 成立。原报告的个数会随数据和分页变化；9–11px 的覆盖及 28px 的文字按钮可在样式中确认。按项目设计约定处理常用页面的文字与触控区。44px 是本项目的操作目标。 |
| 7 盈亏色、正负号与买卖方向 | 部分成立。持仓浮盈和收益率缺少正号与颜色，资产轨迹的首末变化已经有正号，缺的是颜色。沿用本人选定的红涨绿跌，零和未知不着涨跌色。买卖方向另以文字和独立样式表达，错误保留明确提示。 |
| 8 规则重复与口号占位 | 成立。自选列表按市场归并共同准入规则，标的自身的暂停、观察和特殊限制留在行内；估值、轨迹、复盘和现金核对优先展示当前结果，详细口径仍可查阅。移除与操作无关的口号，保留后台状态、时间和缺失原因。 |
| 9a 手机页头的发现按钮 | 成立。窄屏已有底部自选入口，去掉重复的无文字按钮，持仓区仍可发现标的。 |
| 9b 多套筛选 | 部分成立。相同状态选择采用一致的分段控件；复盘的状态计数与筛选合成一组。日期起止、币种等组合条件保留显式应用，允许一次填完再查询；无需让日期与单次点击的行为完全相同。 |
| 9c 详情与日线读数 | 成立。报价、交易入口与走势优先，市场时段、交易资格、计划仍可看。日线增加价格刻度及选日读数，图表与日期控件共用选择，保留键盘与触屏操作、行情时间和未确认收盘提示。 |
| 9d 设置与历史轮次 | 成立。查看历史属于低频只读操作，仍放在设置，轮次列表上移，与公司行动及开始新轮分区。 |
| 9e 复盘混入流水与多处笔记 | 成立。现金核对保留在资产的“明细与换汇”及历史轮次；个人独立笔记收在复盘页的次级入口，与计划或委托下的补充笔记分别说明。 |

报告中八个总体问题分别对应上表的 1–2、3–5 与 9d、1/6/7/9b–c、5、3–4 与 9e、1/6、7 与 9、8。“AI 风格”属于主观评价。本轮采用能观察到的重复、字号、任务路径和信息缺失作为修改依据。

## 业务取舍与交付范围

原评估采用固定时钟、临时 SQLite 与受控行情。它可以衡量布局、还原操作路径，无法证明正式行情和后台撮合行为。保留完整区间成交、参考价时效、撤单等待、回执丢失后使用原请求编号、双设备冲突和分币种记账。部分卖出的收益与最终结果分开。港股模拟下单、自动交易、多账户、实时盘口和技术指标不属于本次整改。

已有阅读减负候选的结论可以采纳。本次以该候选为基础开发，正式合并与本机部署另行安排。界面问题按对日常练习的影响排序；上表中的阅读与外观问题没有证据表明账本计算错误。

## 隔离验收

为复核原数字，使用原审查的固定时钟、同一组四只持仓与合成行情，分别运行基线和候选构建。服务只监听本机，使用临时 SQLite 并关闭后台撮合。正式目录中的采样记录、个人数据库、前端包及服务均由原会话保留。前期用 Playwright 驱动 Chrome 还原原始测量。用户随后指定后续浏览器操作使用 Ego Lite；最后的交互复核使用本机 ego-browser 技能，通过 CLI 直接操作 Ego Lite。

- 另测 320、700、768、1024px，合计六个宽度均可直接读取人民币市值与原币浮盈，持仓区与页面均无横向滚动。受控缺汇率时仍保留原币金额。桌面、手机的四个主页面探针均未发现低于 12px 的可见文字或小于 44px 的可见操作目标。该探针结论限于本轮打开的页面状态。
- 两种屏宽各走通持仓 → 详情 → 交易 → 预览 → 提交 → 撤单 → 来源委托复盘 → 保存正式结论。手机预览标题进入距视口顶部约 149px 的位置。点“保留委托”发送零次撤单请求，确认后发送一次。来回查依据保留未保存的结论；提交回执取自临时服务实际返回的订单编号。
- E1 复盘与阅读减负分别通过 28、10 个浏览器场景，包括从非首批的第 38 笔委托直达、补充笔记绑定准确的订单、508 笔历史覆盖、正式结论保存与导出、过时草稿处理、归档只读及返回原控件。
- 交易专项另走通 11 个受控场景。图表另测 6 类数据，覆盖选日联动、极大与零成交量、单日、空日线及失败；另查三位小数的 ETF 和平价刻度。本轮只用合成报价，不代表重新验收真实市场成交。
- 资产、现金和归档回归完成 51 个界面、下载或核对观测，包括缺汇率保留原币金额，500 余笔流水分页以及归档后只读。
- Ego Lite 在 390px 视口复测，持仓标题仍为 619px，首只持仓显示原币浮盈与收益率。通过“写复盘”打开所选委托，输入结论、回看依据、返回后草稿仍在；保存成功，关闭后键盘焦点回到原来的“写复盘”。还在图上对应的日期控件选择另一日，读到该日收盘价和成交量；买入预览显示费用与资金占用。使用专用测试 Cookie 与临时账户。
- 前端完整测试 196 项通过。最后一次调整后，另重跑 194 个不启动浏览器的测试，并以 Ego Lite 验证上述交互。TypeScript 类型检查与 Vite 生产构建通过。真实手机 Safari/PWA、软键盘、安全区和正式行情时效仍需在相应环境观察。未进行正式部署或远程 CI。

独立代码复核覆盖资金与价格精度、归属、归档和失联保护，未发现阻塞项。本机截图与测量记录保存在候选工作区的 `.omo/evidence/experience-20261119/`。本人想看体验时，可先对照手机持仓、交易预览和复盘截图。若后续安排真机验收，一次连走“读盈亏 → 打开详情并返回 → 查看所选委托的复盘依据”即可核对主要变化。
