# 0.5.0 今日涨跌：分时段采样操作

本说明只用于真实行情的只读核对，不会开放市场、下单、启动应用或重启正式服务。执行代码来自 `codex/0.5.0-market-view` 的独立 worktree。尚未取得的时段一律未验收，不能用其他时间的结果替代。本轮没有创建跨天自动唤醒任务；按本人允许的备用方案交付完整命令，需要本人在下列时间启动。

## 为什么上午和下午分别执行一次连续会话

名单为基础目录 60 项与个人启用/自选观察 181 项，共 241 项。原脚本逐只读取日线再取报价，全名单约需半小时，无法准确覆盖 09:21 和 09:28 两个相邻时点。

本次仍使用 `v050_reference_probe.py`，采样顺序改为：规定时点先分批读取腾讯报价（每批最多 50 只），用分支中的 `parse_quote` 与 `parse_previous_close` 逐项解析，只在内存保存；上午最后一个时点、下午最后一个时点采完后，再逐只读取日线核对。每次真实请求结束后至少间隔 1 秒再开始下一次请求；整个会话只有一个请求执行线程，不并行发请求。采样专用客户端禁用隐式重试和重定向，HTTP 错误、网络错误与超限响应直接记为失败，防止内部重试绕过间隔；产品客户端未改动。批量响应遗漏、重复或多出证券时，该批记为失败，不尝试用假数据补齐。

日线、原始响应、现价及昨收不落盘。结果仅含采集时间、报价时间、报价日、基准日、前一交易日收盘减昨收的 Decimal 差值、相等结论和请求指标。新增差值仅用于人工核实除息；脚本不会自行把不符改成通过。

**一次只运行下面一个采样命令。** 上午会话在 09:35 报价捕获后仍需完成日线核对，等待结束即可；下午同理。不要同时开逐时段独立进程，否则会破坏全局串行要求。电脑必须保持开机、联网，Terminal 不关闭；命令用 `caffeinate -i` 防止空闲睡眠，但不能抵御关机、断网或合盖睡眠。开始连续会话后无需每个时点重新操作。

## 文件位置与判断方式

- 分支工作目录：`/Users/fuhaotian/.codex/worktrees/stockmock-050-change/StockMock`。
- 持久证据目录：`/Users/fuhaotian/Documents/ChatGPT/StockMock/.omo/evidence/0.5.0/`。脚本与原版辅助脚本也在这里备份，删除 worktree 前不能删除证据。
- 个人名单：上述 worktree 内 `work/stockmock-symbols.txt`。不从正式数据库获取名单。
- 每个会话生成 `*.json` 汇总与 `*.jsonl` 逐项结论；`*-capture.log` 记录批次开始/结束时间与汇总。
- `match` 为严格相等；`mismatch_needs_primary_evidence` 必须人工核对一手派息依据、证券、报价市场日、币种和差值，再作判定。其他错误或缺数据均不通过。
- `previous_close_equals_bar_days` 用于辅助识别昨收是否仍对应旧交易日，不能代替一手除息依据。应结合相邻时点的 `quote_time`、`quote_day`、`base_day` 和差值检查是否滚动不同步。
- 时段归属看每项 `retrieved_at` 的北京时间，不看文件名。若网络阻塞或电脑休眠导致实际捕获偏离规定时点，必须标记该时段缺失，不能因为文件名含目标时间就算通过。

以下命令均显式设置临时 `PAPER_DB`，不会读取正式账户数据库。使用 worktree 自有 Python 环境；若 worktree 被移除，需要先恢复分支工作目录和依赖，不能直接改用主目录产品代码。
