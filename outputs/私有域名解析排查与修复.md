# 私有域名解析排查与修复

更新时间：2026-10-23。状态：当前 Mac 的私有域名普通访问已修复并完成验收。系统后缀解析规则已安装；普通 HTTPS、独立浏览器登录、四个主要页面与刷新保持会话均通过，公共网络和本机常驻正常。用户随后确认 iPhone 实机四项通过，见[iPhone 实机验收记录](iPhone实机验收记录.md)。Mac 整机重启验收继续后置，当前无需本人操作。

## 实际原因与对照

StockMock 本机服务、Tailscale Serve 与真实证书正常。故障在当前 Mac 的 DNS 与代理共存路径：Tailscale 本机未接受网络 DNS，普通私有域名被 Clash 映射成 fake-IP；直接询问 Quad100 能取得正确地址。

| 路径 | 实测结果 | 决定 |
| --- | --- | --- |
| 原始系统解析与普通 HTTPS | fake-IP；TLS 失败 | 故障已复现 |
| 直接询问 Quad100，再仅为测试请求指定正确地址 | HTTPS 200，证书验证成功 | 服务、证书与实际私网路由可用；不算普通入口修复 |
| 启用本机 `accept-dns` | 私有 HTTPS 200，但系统加入默认 Quad100，部分公共访问失败 | 已回退；不能作为最终方案 |
| 只补 Clash 私有后缀 fake-IP 排除与 Quad100 定向解析 | 假地址消失，但内核 DNS 查询超时；公共访问正常 | 已原样回滚 |
| 同一 DNS 请求走系统路由或绑定物理接口 | 系统路由得到正确答复；绑定物理接口超时 | 确认代理自动接口绑定与私网 DNS 路由冲突 |
| 系统私有后缀规则安装后 | 系统解析匹配 Quad100，普通 HTTPS 200；浏览器与公共访问全部通过 | 当前 Mac 私有域名项关闭 |

两次应用重启都通过正常退出及 LaunchServices 后台启动完成，没有强杀内核。原代理模式、端口、TUN 启用状态和手选节点保持一致；Tailscale DNS 偏好和 Clash DNS 文件均恢复到排查前状态。没有修改 hosts、默认系统 DNS、交易数据或 Serve 范围。

## 已应用的修复

使用 macOS 原生的 `/etc/resolver/<实际私有后缀>`，仅把该后缀交给 Quad100，保留默认公共解析。已核实安装文件与准备内容逐字节一致：

```text
nameserver 100.100.100.100
timeout 2
```

macOS 本机 `man 5 resolver` 说明：目录中的文件名作为解析域，系统按最长域后缀匹配选择解析器。这个方案使用系统路由，不写死临时 `utun` 编号；本次已实际生效，无需重启整台 Mac。磁盘规则的安装与当前有效状态均已核验，整机重启后的状态仍按用户决定后置。

当前主机的辅助文件位于被忽略的 `work/private-dns/`。`install-system-resolver.sh --check` 和 shell 语法检查通过；脚本仅接受已准备的私有后缀、拒绝覆盖不同内容或符号链接，支持 `--remove` 精确撤回自身规则。私人后缀、备份、操作记录不进入公有仓库。

此前所需的管理员安装步骤已经完成，不必再次执行。确需撤回本次规则时，在当前主机的项目根目录运行：

```bash
sudo /bin/sh work/private-dns/install-system-resolver.sh --remove
```

脚本只删除内容仍与本次安装完全一致的规则，保留其他解析配置。密码只在 Mac 的 Terminal 中输入，不发送给智能体。撤回会恢复先前私有域名解析失败的状态，日常使用无需执行。
