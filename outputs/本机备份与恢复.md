# 本机备份与恢复

本说明适用于单个人本机账户。备份保存在本人私有、Git忽略的本机目录，不上传、不云同步，也不新增自动备份服务。数据库、密码和运行配置必须成套保存；单独保存数据库不能保证移动目录后可正常登录和启动。

2026-10-24 已完成 0.4.1 隔离恢复演练，实际范围见[本轮集成验证](0.4.1集成验证.md)。演练使用完整受控测试账本、测试密码及独立规则，未覆盖正式账户。真实个人账户的正式恢复只在本人明确需要时进行，不能把这次演练理解为已替换正式数据。

0.4.5升级边界：新程序可以读取旧快照JSON，新增首次失败元数据后，0.4.4的严格字段检查可能无法读取新记录。发布保全用于核对和保留现场，不代表只切回旧代码即可安全回退；尤其不能用升级前数据库覆盖升级后新产生的账本。正式异常时停止已核对归属本项目的服务，保留当前库和现场并向前修复；若另需兼容回退，先验证具体方案。0.4.5已在新私有目录完成正式保全和原库升级，切换时0活动单、当天不完整0、旧10表保持；没有恢复覆盖账户，实际结果见[执行记录](0.4.5执行与验收记录.md)。

## 应保存的完整材料

| 材料 | 用途与注意事项 |
| --- | --- |
| `backend/data/paper.sqlite3` 的一致副本 | 包括所有轮次、现金、订单、幂等请求、流水、快照、公司行动、计划、提示、普通笔记、正式结论、监测状态和动态资格；运行中使用SQLite在线备份 |
| `backend/.local-password` | 保持原访问密码；当前用户所有、普通文件、权限0600，不打印内容 |
| `backend/.runtime.json` | 保存Host、Origin、安全Cookie及人工暂停等原设置；当前用户所有、普通文件、权限0600 |
| 配置中 `STOCKMOCK_INSTRUMENTS_FILE` 指向的文件 | 配置引用外部证券规则时必须一并复制；移动后把绝对路径改为恢复副本中的路径 |
| 对应源码与版本 | 保留已部署版本对应的源文件或源码归档，不能只保留一个未来会更新的工作目录 |
| `backend/pyproject.toml`、`backend/uv.lock`、`frontend/package.json`、`frontend/bun.lock` | 按对应版本恢复Python/Bun依赖；不混用其他版本锁文件 |
| 对应 `frontend/dist` | 保留正式前端包；也可用对应源码和锁文件重新构建。候选测试包必须放独立目录 |

已有数据库时不能把单独复制一个正在写入的SQLite主文件当作完整备份；WAL中可能仍有已提交数据。两种可选方式是运行中调用SQLite在线备份，或正常停服后复制整个数据库目录。后者必须先确认本项目进程已结束，不能只复制主文件并遗漏同目录的WAL/SHM。

## 正式数据仍运行时的本机备份

以下路径均为占位，请替换为自己的项目及私有备份位置。不要将密码、配置正文或私有入口粘贴到终端命令、截图或公共报告。备份目录必须在忽略目录内且权限0700，文件0600；若迁移到其他位置，先确认未被Git或云同步纳入。

1. 记下当前实际部署版本，确认源码归档、静态包与这个版本一致。保留旧版源码/锁文件作为回退材料。`git archive`只包含已提交源文件，不包含忽略的密码、配置、个人库及静态包，这些需要分别复制。
2. 建立私有目录并做在线一致备份。下面代码不会停止正式服务，也不会执行数据库升级：

```sh
cd /路径/StockMock
umask 077
backend/.venv/bin/python - <<'PY'
from pathlib import Path
import os, sqlite3
root = Path.cwd()
backup = root / 'work/private-backup/本次备份标识'
backup.mkdir(parents=True, exist_ok=False, mode=0o700)
source = root / 'backend/data/paper.sqlite3'
if not source.is_file():
    raise SystemExit('原数据库缺失，停止备份，不能创建空账户')
with sqlite3.connect(f'file:{source}?mode=ro', uri=True) as src:
    with sqlite3.connect(backup / 'paper.sqlite3') as dst:
        src.backup(dst)
        if dst.execute('PRAGMA integrity_check').fetchone()[0] != 'ok':
            raise SystemExit('数据库完整性检查失败')
os.chmod(backup / 'paper.sqlite3', 0o600)
print('在线一致备份完成；仍需保存配套配置、规则、密码和源码')
PY
```

3. 把密码、运行配置、配置引用的规则文件、对应源码归档、锁文件和静态包复制进同一私有备份目录；记录原路径与恢复相对路径的对应关系，但不记录或打印秘密内容。确认目录0700、文件0600、当前用户所有、没有符号链接。未配置外部规则可在清单记录“不适用”；已经配置的引用文件缺失则必须失败。
4. 使用只读SQLite连接核对表及记录数量，并保留本次清单。金额和JSON嵌套字段必须按原始值比较，不转换成浮点数。快照和监测状态可能随正式后台正常增长，因此比较时以在线备份取得的同一副本为准。

## 先隔离演练，再决定正式恢复

恢复目录与备份源分开，永远保留源副本。先复制源码、数据库、配套私有文件和锁文件到新的候选目录；不要直接指向正式数据库，也不要把正式端口8000抢给测试进程。按锁文件安装依赖（后端`uv sync --frozen`，前端`bun install --frozen-lockfile`），前端使用独立输出目录构建。依赖目录不可跨系统当作可靠可移植备份。

恢复时必须逐项确认数据库、密码、运行配置及已声明的外部规则均存在，不能因缺配置而接受默认空设置，也不能因为没有数据库而启动出新账户。复制后将 `STOCKMOCK_INSTRUMENTS_FILE` 改为恢复目录中的规则副本；不要让候选继续读取原位置。权限不正确时先修复为本人所有、目录0700和文件0600。密码文件保持原值，不能为了通过检查改成新密码并宣称原登录已经恢复。

用恢复版本的真实`--check-config`检查配置与依赖；0.4.1检查通过只表示配置/依赖有效，未启动服务，不证明行情或后台已工作。随后在隔离端口用真实应用、数据库、认证和两个worker启动；行情必须禁用网络撮合或采用明确受控来源。本轮使用专用测试入口替换端口、时间与外部行情，其余应用及生命周期真实运行；没有让固定8000的正式启动器抢占端口。

实际核对当前及归档轮次、所有表所有字段、精确金额、订单与请求、流水、计划/提示/笔记/结论、快照、公司行动和资格；认证后读取实际API。等待后台自然运行，核对两个worker的时间推进。升级只允许写恢复副本，保留升级前源库和对应旧版本源码，必要时先用旧版本只读解析源库，不能把升级后的副本当作唯一回退材料。

若本人以后确需替换正式账户，先对当前正式账户再做一套完整备份，再用 `backend/.venv/bin/python scripts/service.py stop` 正常停止确认归属本项目的服务。确认已停后才替换已验证的完整数据库目录及配套材料，修正正式路径和权限，然后运行检查并通过`service.py start`启动。启动后重新认证核对原记录、资格与两个后台任务；失败时保持停止状态，依据刚保留的完整副本恢复，不得静默新建账户。本轮没有执行这一步。

## 失败时怎么定位

缺失数据库/配置/密码/规则时先补齐备份，不要继续启动。权限错误按当前用户及0600/0700修正；依赖缺失按同版本锁文件安装。0.4.1的安全日志位于 `backend/data/logs/service.log`，当前日志及最多三份轮转历史有大小上限；日志不可写时检查安全标准错误，不假定错误已经记录。

若Python解释器不存在或操作系统拒绝启动，Python日志本身不能工作。先运行 `backend/.venv/bin/python scripts/service.py status`（解释器可用时）并检查本项目系统任务状态；不要卸载未知同名任务，也不要杀死占用端口的其他进程。Mac整机重启及iPhone体验仍属于本人验收，候选服务重载不能替代。

## 本轮已经实际验证的操作

本轮从既有受控账本复制后，通过真实公司行动函数补充一笔股息，加入合法动态资格及外部规则，再保存为源副本。恢复前后全部表及字段相同：36轮、822计划、52提示、71结论、60请求、31快照、1公司行动和1动态资格。普通笔记、现金、持仓、订单和流水保存在轮次JSON内，同样完整比较。

恢复源保留0.4.0源码与锁文件，旧源码在只读URI上成功解析源库；0.4.1真实启动器在隔离根运行，真实HTTP先返回未认证401、登录后各读取返回200，两个后台自然推进。恢复工具分别在缺运行配置、密码和规则时拒绝启动；启动器另外实际拒绝错误密码权限、缺规则和缺Python依赖，均未创建空数据库。源码未修改产品规则，所有材料仅在忽略目录。

复跑入口是 `work/0.4.1/qa/recovery_prepare.py`、`recovery_run.py`和`recovery_checks.py`；已有证据目录不覆盖，重新演练应使用新输出目录。`recovery_run.py`在停止信号后自行关闭候选进程、核对原记录保全并写清理收据。具体证据与本轮清理状态以[集成报告](0.4.1集成验证.md)为准。
