本版聚焦“哪些判断还需要复盘、上次结论是否覆盖最新成交、当时计划与实际操作有什么差别”。保持资产、自选、委托、复盘四个入口，改进现有复盘页和详情，不另建独立统计系统。

## 模块一：正式复盘结论与覆盖范围

普通笔记保持原用途和原数据。新增明确的“保存本次复盘结论”，填写“本次结论”（去除首尾空白后1–2000字，必填）、“与原计划的偏差”（可空，最多2000字）、“下次怎么做”（可空，最多2000字）。不自动生成、打分或把计划结束当成复盘完成。计划、无计划旧委托都可以保存；未成交也可记录撤单或观察结论。

结论采用追加记录，后续修正通过“补充复盘”新增，旧内容不覆盖。本版不做结论编辑或删除。沿用已有计划表的方式新增独立 `review_conclusions` 表，包含普通UUID主键、轮次、主体类型 `plan|order`、主体ID、三段文字、服务器保存时间及覆盖事实；按轮次和主体建立普通索引。原 `State`、`Plan`、`Order` 的持久JSON不新增字段，避免旧版本严格模型无法读取，使0.3.0程序可忽略新表继续读取原账本。无计划旧委托单独作为主体；已有计划的委托统一归该计划，不能再形成第二份独立完成状态。旧笔记原样保留并标“普通笔记”；不自动迁成正式结论。

覆盖事实包括：用户读取时的计划版本（旧委托为空）、已确认成交订单ID集合、当时已到达的计划复盘日期（未到或未设置则为空），以及当时最近结论ID。详情一次一致读取返回上述元数据和全量成交摘要，前端随表单带回，不从已加载的订单页推算。用户能看到“本次覆盖计划第几版、几笔成交、是否到复盘日”；不要求逐条点开才能保存。新挂单/撤单、普通笔记、提示已读及价格变化不自动使结论过期；新成交、计划版本变化、约定复盘日期首次到达会使它需要补充。

| 新展示状态 | 判定 |
| --- | --- |
| 暂未到复盘时点 `not_due` | 无正式结论、无已确认成交、复盘日期未到；仍允许主动复盘 |
| 待首次复盘 `pending` | 无正式结论，已有成交或北京时间已到约定复盘日；有普通笔记也仍待复盘 |
| 已复盘 `reviewed` | 最新正式结论覆盖当前计划版本、全部已确认成交及已到达的约定复盘日 |
| 有新进展待补充 `needs_update` | 已有正式结论，但上述三项至少一项变化；逐项说明原因 |

复盘日期沿用现有本人约定，不因草稿、进行中或结束状态自动取消；计划结束也不清空日期。当前轮按北京时间今天判定；归档固定使用归档时刻，不能随着今天推进使旧轮次出现新待办。新版可增加 `review_state`；为旧调用方保留三值 `status`，把 `needs_update`映射为 `pending`，其余同名；旧 `status=pending`筛选包含首次和补充待办。所有状态以服务器计算为准。

保存必须在同一SQLite事务内检查当前轮次、主体归属、计划版本、完整成交ID集合、到期日期和最近结论ID。提交携带普通请求UUID，先检查是否已有成功记录：同ID、相同完整提交内容返回原结论，不重复追加，也不重新执行首次提交的覆盖冲突检查；同ID不同内容始终409。成功重试同时重新计算原主体所属轮次的状态，归档按归档时刻，响应明确原轮次及只读状态；不能据此把新成交自动算已复盘，也不能把原轮次结果拼入新轮次。

只有尚未成功过的新请求才进行当前轮次和覆盖检查。两台设备之一新增成交、改计划、先保存结论、跨午夜到期或切换轮次时，另一台未成功提交的旧表单必须409并保留草稿，提示刷新事实后再保存，不自动扩大覆盖范围。无效关联/跨轮关联不能写入；归档拒绝新写入。结论保存、覆盖检查及一致读取共享同一连接，不能在外层事务内调用再次打开 `BEGIN IMMEDIATE` 的现有 `round_plans()`、`alerts()`等封装；复用或抽取接收连接的读取函数，事务内不做网络请求。只记录普通业务字段和版本，不增加hash或冻结机制。

旧数据兼容：初始化新表为空，重复初始化安全，原订单、计划快照、流水、笔记、计划、提示、持仓、快照、资格和金额不重写。旧账户原先因有笔记而显示已复盘，升级后可能显示待首次复盘，说明“旧笔记已保留，尚未保存正式结论”。结束的计划在当前轮可补充结论；归档只能阅读和下载。归档保留原轮次结论行，新轮从空集合开始。

## 模块二：执行事实与下单依据对照

在复盘详情保留当前计划、实际结果和订单详情，补充按时间排列的“已记录事实”：委托提交、已确认成交、实际提示、普通笔记、正式结论。现有字段若有明确撤单申请或终态确认时间可显示该事实；缺失时间只在订单卡显示当前状态和“确认时间未记录”，不得拿到期时间或当前时间补造事件。计划只显示真实创建和当前版本更新时间，不生成不存在的历次修改事件。

时间线按实际保存的系统时间升序、相同时间按事件类型及原记录ID稳定排序；成交用 `confirmed_at`排序并单独显示市场样本 `filled_at`。旧成交缺确认时间时保留在“时间未完整记录”区并能分页/导出，不按市场时间冒充确认时间。提示保留 `plan_version`、条件、市场时间、观察时间、价格、来源；已读仅表示读过，不代表已执行或已复盘，也不推断某笔订单响应了某条提示。事实分页默认50、最大100，完整读取不能被旧500条详情上限截断。

选择一笔订单后，将当时计划快照与当前计划的方向、理由、目标/止损参考价、复盘日期、失效条件并列，标出变化；同版本也可正常阅读。没有快照的旧委托只显示原订单理由和已有字段，明确“未保存当时计划”；没有历史版本的提示不拿当前计划冒充当时全文。未知金额留空/未知，时间展示北京时间并清楚标注市场时间与系统确认时间。

收益仍只汇总已保存的关联卖单原币净收益，任一必要收益缺失或没有卖单时保持未知；不跨币种相加、不重算旧成本。使用“关联买卖净份额”“本轮该证券实际持仓”“关联卖单原币净收益”，说明前者不是计划专属仓位，部分卖出不是计划最终结果。卖旧仓、同证券多段计划、拆股后数量都按原始事实展示。

## 模块三：复盘工作台、检索与直达

在现有复盘入口顶部显示首次待复盘、待补充、已复盘和暂未到期数量。数量来自完整查询结果，先应用轮次/证券/市场/计划状态/日期条件，再计各复盘状态；点击状态后列表再筛，计数不随分页条数变化。计划状态筛选为全部/草稿/进行中/已结束/无计划旧委托；不把计划状态与复盘状态混为一组。当前轮默认全部待办，归档默认全部状态。

证券按本轮真实计划/订单中的证券选择或代码查找，支持市场CN/US/HK；归属取已保存证券标识和目录信息，确实未知只在全部显示，不能把“关联丢失”猜成某市场。列表日期明确叫“最近记录日期”：取主体创建、计划当前更新时间、订单实际创建/确认时间、提示创建、笔记和正式结论保存时间的最大已知值，不包含提示已读时间、浏览时间和动态行情；日期不会因用户查看而变。开始日含北京时间00:00，结束日到次日00:00排他，倒序日期422。无日期条件时包含全部。

列表按主体不可变的创建时间降序、主体类型和ID稳定排序，避免状态或笔记变化把已翻页项目重排。新增游标查询可以复用旧 `/api/reviews` 或另设 `/api/reviews/page`，旧数组/分页调用保持兼容；每页有总数和轮次。页面加载更多按主体ID去重，不承诺跨请求的实时快照：当前轮明确“有新记录或状态变化时请刷新”，刷新/切筛选丢弃旧分页并从头读取。若翻页间换轮，拒绝拼接并重载。归档固定只读。CSV始终是点击导出时的一次完整读取。

普通笔记单列“笔记日期”筛选，资金核对继续独立；不能让一个无说明的日期控件看似同时筛三种数据。笔记证券/市场先从关联计划解析，再从关联订单解析；两者同时存在须属于同一计划，旧异常明确未知。支持计划笔记、订单笔记、无关联笔记；未关联笔记只在全部证券/市场显示。筛选必须作用于完整数据再分页，不能只筛已加载的25/50条。可新增 `/api/journal/page` 并扩展归档笔记分页，保留旧 `/api/journal`数组兼容。计划笔记提供“查看相关复盘”。

首页及证券详情的提示增加“查看相关计划/复盘”，以 `round_id + plan_id`定位确切详情，不依赖首屏已加载项或证券下第一个计划。到价和日期提示、已结束计划、旧版本提示均能定位，并突出所选提示的原始背景；归档进入同轮只读详情，不能误回当前轮编辑。查看不自动标已读。收起/返回保留来处和列表筛选，目标不存在时明确说明，不能打开另一条记录。

保留原完整计划、提示、复盘及资金导出。新增“导出筛选复盘”：先按工作台同口径确定主体，再导出这些主体的完整订单事实、提示、普通笔记和历次正式结论；不是只导出可见页或只导出日期区间内的子事件。页面与CSV说明“日期用于筛选复盘主体，主体内含完整记录”。CSV新增明确记录类型、主体ID/轮次、版本/覆盖事实/结论字段；文本复用公式注入防护，负金额仍是数字，缺值不填0。旧无参数 `/api/reviews/export.csv` 保留全轮内容和独立无关联笔记；新增字段可追加，不能丢掉旧快照或笔记。真实下载检查编码、中文、换行、逗号、公式文本和超过500条完整性。
