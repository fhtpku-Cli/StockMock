## 当前方案

电脑使用 `http://127.0.0.1:8000/`；手机连接同一 Tailscale 账号，通过私人 HTTPS 域名的 8443 端口访问同一个账户。后端只监听回环地址，Serve 将 HTTPS 转发到本机 8000，使用 `--bg` 保存配置。没有启用公网 Funnel，也不开放路由器端口。

此前 Mac 私有域名被代理映射到 fake-IP。当前已安装系统 `/etc/resolver` 私有后缀规则，普通系统解析返回正确节点地址，正常 HTTPS 与独立浏览器登录、四页导航和刷新保持会话通过；公共访问及既有代理模式、节点和 TUN 状态正常。仅该后缀使用 Quad100，试验性的 Clash DNS 与 Tailscale 全局 DNS 变更均已撤回。详见[私有域名解析排查与修复](私有域名解析排查与修复.md)。手机使用自身 Tailscale DNS，不能由 Mac 结果推定其已连通；真机验收使用原 HTTPS 域名，不改成 IP。

后台使用 macOS 当前用户的 LaunchAgent，登录后启动单个后端进程、异常退出后恢复。密码由项目本地受限文件读取，不写入 plist、启动参数或公开报告。数据库保持在 `backend/data/paper.sqlite3`，日志和私有配置均被 Git 排除。

## 实际常驻与边界

本轮核对原临时实例身份后正常停止，确认端口释放，再启动已安装且属于本项目的服务。实际服务父进程为 launchd；登录及账户读取成功，原轮次与资金保留。正常终止服务进程后，观察到新的进程自动拉起，再次登录和账户读取成功。后台处理时间在后续一分钟推进，最终保留正式常驻运行，只有一个 Worker 监听 `127.0.0.1:8000`。

关闭网页、终端或 Codex 不会结束由 launchd 管理的服务。登录后自动加载配置已核验，但本轮未注销用户或重启整台 Mac，以免中断其他工作。注销、关机和主动休眠会停止处理；当前接电设置已不自动休眠，无需修改全局电源设置。重启服务后会话失效，需要重新登录，账本不会重置。网络与服务恢复后仍遵循原订单截止规则，不补造停机期间成交。

## 后台服务管理

从 StockMock 项目根目录执行。使用已安装的项目依赖，启动时不联网安装软件。已有正式实例时无需再次 install。

```bash
backend/.venv/bin/python scripts/service.py status
backend/.venv/bin/python scripts/service.py stop
backend/.venv/bin/python scripts/service.py start
```

首次安装使用 `install --dry-run` 查看配置，然后 `install`；仅需移除本项目后台服务时使用 `uninstall`。停止或卸载会保留源码、数据库、密码与日志。端口冲突时拒绝启动，不终止其他进程；同名服务归属无法核对时拒绝覆盖或停止。停止会等待精确任务卸载，超时明确报错并保留配置。

服务工具是 `scripts/service.py` 与 `scripts/run-service.py`，使用项目 `backend/.venv/bin/python`。密码在 `backend/.local-password`，运行设置在可选 `backend/.runtime.json`；两者必须由本人拥有、权限为 `0600`，不接受符号链接。JSON 设置仅接受既有白名单字段，不执行 shell，也不保存密码。更改设置后需停止再启动服务。

日志位于 `backend/data/logs/service.log`，每份约 1 MB，保留三份轮转，不输出访问密码。工具状态区分安装、加载、进程与端口；实际行情和后台处理状态仍应查看应用中的最近处理时间。

## 私有 HTTPS 管理

PM 已核对路由归属并实际执行以下启用命令。停止时只关闭本项目 8443 入口，禁止使用会影响其他服务的 `serve reset`。

```bash
/Applications/Tailscale.app/Contents/MacOS/Tailscale serve status --json
/Applications/Tailscale.app/Contents/MacOS/Tailscale serve --bg --https=8443 http://127.0.0.1:8000
/Applications/Tailscale.app/Contents/MacOS/Tailscale serve --https=8443 off
```

后端运行设置已精确允许本项目主机和 HTTPS 来源，未设置通配符。Uvicorn 仅信任来自 `127.0.0.1` 的代理转发头。真实入口未登录返回 401，跨站写入 403，非法 Host 400；Cookie 具备 Secure、HttpOnly 和 SameSite=strict 属性，退出后不可再读账户。HTTP 本机与 HTTPS 远程会话独立，但读取同一轮次和资金。
