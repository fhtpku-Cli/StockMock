## 产品与技术决定

### D1　盘后参考日线必须在参考交易日实际收盘后取得（B13）

1. 仍取订单生效交易日紧邻前一交易日的未复权日线。用交易所日历的实际`session_close`，不能把A股应用截止14:57当成日线收盘15:00。周末、节假日、跨月按同一日历；不沿用缺失多日或更早的日线。
2. 当参考日尚未实际收盘时明确拒绝并说明等待收盘参考；因此A股14:57至15:00不受理次日预挂单，不退回前一日价格。15:00起仍须取得合格日线，不能只看墙钟就接受旧缓存。新单20分钟分钟行情保护保持，日线合格不等于其他受理条件自动通过。
3. `MarketDataClient.history`增加可选最早取得时刻约束，普通图表读取默认行为不变。同一客户端锁内检查已有缓存；早于要求时按需重新请求，合格缓存继续复用，并发同要求不得各自重复刷新。必须实际绕过过早缓存；单传`ttl=0`不能绕过已存在的未过期条目。
4. Engine最后验证参考日期、证券/币种/来源、正且有限价格，以及带时区的`参考日实际收盘 <= retrieved_at <= 本次真实校验时刻`。保留现行公司行动参考保护。刷新失败、只有旧日期或异常数据时明确失败，不回退盘中缓存；保留B07的短错误缓存及恢复、其他证券和US/FX正常缓存语义。
5. Preview、place及sizing均通过同一prepare规则。已受理订单的`daily_lower/daily_upper`不回写；后续来源修订不改变旧单或账本。收盘后取得表示采用当时观察版本，不承诺供应商永不修订，不新增固定定稿等待。
6. 当前Provider协议与受控provider需适配。market_data负责行情接口实现，trade_engine负责协议调用与最后校验；接口先在执行记录确认后分头修改，不互相编辑对方文件。

### D2　资产快照采用当天首次成功保存的完整观察（B14）

1. 只允许当前轮、同一北京时间日的已有missing/stale记录升级为complete。保留原行id和`(round_id, day)`唯一键；complete、过去日、归档轮次永不重算。不补造离线日期或收盘净值。
2. 当天首次不完整记录仍及时保存。若当天后来取得完整估值，用本次真实余额/持仓及行情生成完整记录，主`captured_at`和`price_times`指向恢复观察，主`issues`只表达当前状态。重复失败不覆盖第一次失败；增加可空首次失败元数据，保存原时间、状态和原因，默认空值兼容旧JSON。未发生失败的完整记录不虚构失败信息。
3. 在事务外采集，在短写事务内重新读取当前行和账户状态。多个complete竞争时，以首次成功提交者为准，迟到失败或后续complete不得覆盖；不能宣称先开始采集者必胜。账户交易、现金、公司行动或换轮造成State变化时丢弃本次混合观察，下个tick再试，不延长SQLite事务等待网络。
4. 采集开始和结束都核对真实北京时间日期；跨午夜结果不写入前一天，下一tick再为新日采集。时间入口允许受控测试注入，真实运行不得沿用静止测试时钟。观察时间采用本次真实采集时刻并写清起止含义，不把恢复值写成首次失败时刻；不得把返回前尚未取得的行情标为已取得。
5. API、曲线、区间首末变化、页面说明同步。范围仍只用两个不同日的实际完整首末记录计算；当天恢复后刷新/重入可见，不新增定时刷新保证。页面显示“当天完整观察时间”和首次未完整说明，不能把历史缺口消失说成重新取得历史价格。
6. 快照CSV保留现有8列，末尾追加首次失败时间、状态、原因三列；旧记录为空。主金额和时间与API一致，原精度及CSV安全处理保持。
7. 新程序必须读旧JSON；旧程序的严格字段检查可能不能读新增元数据。不得声称只切回0.4.4代码即可回退，也不得用保全库覆盖升级后的个人账本。候选验收先在隔离副本验证升级与读写；正式异常保留现场、停止已核对的项目服务并向前修复，不能牺牲新账回滚。执行者如选择另做兼容回退，必须先提出证据和方案复核，不自行扩大迁移范围。

### D3　“按原参数再下单”始终建立新草稿（B15）

1. 仅当前轮`cancelled/expired/terminated`显示入口；filled、accepted、cancel_pending及归档单无此入口。证券仍须按当前资格重新检查。
2. 草稿复制原证券、方向、订单类型、数量、限价、理由、目标和止损；不复制生效时间、预留、成交、日价格边界或旧请求号。必须重新预览并由用户明确提交，不点击入口即下单。原单、原计划快照与历史事实保持原样。
3. 有原关联计划时读取当前计划。仍可用则按当前版本关联并明确提示版本变化，保留复制的委托理由/目标/止损，不由PlanPicker静默覆盖。用户主动选择其他计划时沿用明确选择带入的既有行为。
4. 计划已结束、归档、不存在或读取失败，明确显示原因并阻止含糊提交；允许重试，或由用户明确选择“不关联计划”继续。不得因网络失败静默解除关联。计划在预览后变更、换轮、资金/T+1/规则变化，继续由当前服务端校验拒绝或要求重预览，保留草稿。
5. 新草稿用新request_id；对这个新请求的网络未知重试沿用同一request_id，编辑有效参数则遵守现有失效与换号规则。保留离线禁写、提交期间保护和B05/B06跨轮、归档幂等行为。不新增后端克隆订单接口。

### D4　解释首个候选完整区间，不承诺成交时间（B16）

1. 服务端基于`active_at`与适用截止计算第一个完整五分钟连续交易区间，复用撮合日历/闭区间规则。Preview及订单只读响应投影返回可空起止与“有候选/确实无候选/日历未知”状态；不写回持久Order、不让前端复制市场日历。日历未知返回说明，不猜时间、不使已有订单无法读取。
2. 10:01或恰10:05生效→10:05–10:10；11:28生效→13:00–13:05；CN14:53至14:57无完整候选。US普通/提前收盘、夏令时、节假日及秒/微秒用真实日历验证。结束等于截止仍有效。
3. 这表示按生效条件计算的首个候选，不是下一根未处理区间。撤单改变截止后重新投影；已过去区间用“首个候选区间为”，不能写“将在……成交”。预挂单先说明生效时刻；无候选说明不会新增成交机会、等待后台确认；日历未知诚实展示未知。
4. 保留“有效行情到达并满足价格条件才可能成交”和撤单待确认占用说明。后台约每分钟检查受网络与来源影响，不能用网页刷新频率或worker.last_run+60秒给出倒计时，也不能保证20分钟内一定终态。终态以实际记录为主，不给旧记录补造确认时间。

### D5　汇率只改展示，不改金额或日期语义（B17）

TradePreview、OrderDetails和Cash共享展示函数：1单位外币对应人民币保留六位小数，使用十进制字符串处理或现有精确方案，不能先转浮点再参与计算。日频FX的市场时间按来源日频日期展示为“YYYY-MM-DD 日频参考”；当前来源UTC日标签不得经本地时区伪装成08:00发布时间。取得时间若另展示，明确叫取得时间。缺失历史字段保留未知，不从自由文本推测。API原值、计算、订单与流水历史、CSV精度都不改变，不解析/改写旧流水说明。
