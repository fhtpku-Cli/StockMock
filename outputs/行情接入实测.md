### 美股日线（当前已接入）

新浪官方 SDK 的 `US.DAYK_URL` 返回编码历史，现已通过同一官方 [sf_sdk.js](https://finance.sina.com.cn/sinafinancesdk/js/sf_sdk.js) 中独立解码函数读取。生产入口 `MarketDataClient.history()` 对 AAPL、SPY、NVDA 实际分别返回 252 条日线（2025-10-21 至 2026-10-21），末日收盘均与独立腾讯快照一致，缓存命中保留最初取得时间。不存在用分钟样本拼造日线的路径。

未复权口径依据实际历史断层交叉检查：AAPL 2014 年七拆一、2020 年四拆一，NVDA 2024 年十拆一，拆股前后保留当日实际价格数量级，没有把旧价格回调到新股数口径。事件日期来自 [Apple 官方拆股说明](https://investor.apple.com/investor-relations/faq/default.aspx)和 [NVIDIA 官方公告](https://nvidianews.nvidia.com/news/nvidia-announces-financial-results-for-first-quarter-fiscal-2025)。ETF SPY 同样实际取得有效 OHLCV，末收盘与独立快照一致。这是已观察样本的口径证据，不是供应商对全部证券未来数据的正式合同保证；仍未获得自动公司行动数据。

使用维护中的 [quickjs-ng](https://github.com/genotrance/quickjs-ng)，每次解码独立解释器，0.5 秒 CPU、32MB 内存、512KB 栈；不注册宿主函数、文件或网络模块。SDK 仅提取预期独立函数，结构变化明确报错；不执行完整 SDK，不把脚本作为 Python 或 Node 执行。输入各上限 1MB，输出上限 1MB；严格解析带日期 OHLCV，未收市日线排除。脚本缓存 24 小时、日线 1 小时，仅在进程内存中；原始脚本不纳入公有源码。测试实际触发超时、内存耗尽、宿主访问失败和变化响应拒绝。

### 港股限制与已完成适配

新浪官方 `datas/t.js` 的港股分钟端点实际返回 HTTP 200，但只有时分秒、价格和量，没有日期，不能用检索日期补造。腾讯分钟重定向后 TLS 失败，未绕过；东方财富用途限制维持不集成。Yahoo 正常间隔重试一次仍为 HTTP 429，已停止。

已实现仅连接 `127.0.0.1` 的 Futu OpenD [官方 JSON TCP 协议](https://openapi.futunn.com/futu-api-doc/en/ftapi/protocol.html)及[历史 K 线](https://openapi.futunn.com/futu-api-doc/en/quote/request-history-kline.html)：显式 `rehabType=0` 不复权、`klType=6` 五分钟，有限超时、包长上限、官方校验字段及权限错误，不访问交易接口。实际本机连接返回 `futu_unavailable`，不能声称真实港股账户行情通过。

本人后续只需完成一个人工环节：启动并登录本机 Futu OpenD，按其要求确认本人 API 协议和行情权限。程序配置 `STOCKMOCK_FUTU_PORT`；接入验收从真实带日期记录核对标签后再配置 `STOCKMOCK_FUTU_BAR_LABEL=start|end`。默认不猜标签，不自动启用港股。受控 TCP 对端验证了请求及权限错误，仅证明协议行为，不代替真实账户结果。

具体由本人在[富途官方下载页](https://www.futunn.com/download/OpenAPI)选择 macOS OpenD，安装后登录自己的账号，保持监听本机端口（通常 11111），查看港股行情权限及 API 协议状态。没有账号时不要由智能体代注册，是否注册由本人决定。官方免费说明不代表当前账号一定有权限。本人完成登录后，开发验收再检查 `00700` 与 `02800` 的日期、五分钟标签和未复权响应，配置端口/标签并通过导入工具启用；不要让用户凭猜测填写 `start/end`。

本人负责提供真实官方元数据；程序检查映射、币种、类别和规则，然后实际请求报价；设为可交易时还须取得近期完整分钟线。重复代码、供应商别名、`AAPL` 错映射 `usMSFT` 均拒绝。全部通过才写新文件，不覆盖旧文件。设置 `STOCKMOCK_INSTRUMENTS_FILE` 为输出文件并重启，记录与内置目录合并，同代码可显式更新；港股真实验收后也无需修改源码才能启用。

所有最新数据日期为 2026-10-21。中国市场的最后分钟区间截止于北京时间 15:00；取得时距该截止约 13 小时 51 分钟。美股快照距取得约 51 分钟。上述差值是“数据时间距取得时刻的间隔”，包含正常休市，不能说成数据源盘中延迟。腾讯境内时间在收盘后一小时以上，更不能把该字段当作真实成交时点。`quote()` 因而始终返回 `tradable=False`，用于估值及预览。

四个境内分钟集合的时点均包含 09:35、11:30、13:05、15:00，不含 09:30；末条收盘价与独立腾讯未复权日线一致。这是本轮支持“五分钟末端标签”的实测依据，仍缺供应商正式时间语义和持续盘中验证。每条分钟候选保存 `interval_start=end-5m`、`market_time=end`、正成交量、取得时间与来源，过滤未完成和零成交量区间。`tradable=True` 表示可交给交易层检查的区间候选，不等于已经通过所有交易规则。特别是 14:55—15:00 区间跨过 14:57 后集合竞价，交易层必须拒绝；不能只看区间末端是否小于或等于 15:00。

日线只接受 `day` 未复权序列，不偷偷改用 `qfqday`。日线 `market_time` 是当地日期零点转换后的日期标签，绝不是成交时间；撮合不得使用日线。日线成交量保留来源单位，没有跨市场统一成股数，不能与分钟成交量直接相加。未得到可直接处理的分红、拆股事件；没有自动公司行动能力，相关持仓收益和调整仍须个人核对，不能标为已正确自动派息。

## 汇率

Frankfurter v2 返回 2026-10-21 的 HKD/USD 对人民币日频参考值；适配层使用 Decimal 倒数，统一得到每单位外币对应的人民币价格，真实数值保留在本机证据中。CNY=1 是币种恒等值，来源单独写为 `currency-identity`，不冒充网络返回的行情。

[Frankfurter 官方说明](https://frankfurter.dev/)称 v2 默认为多个官方来源混合的日频参考值，不是实时交易价格，并允许本地缓存。接口只提供日期，没有确切发布时间；`market_time=该日期 UTC 00:00` 仅用于日期表示，报告和页面不得称其为实际发布时间。外层必须显示日期、缓存日频结果并检查过期，不能因接口连通就无限期使用旧汇率。v1 本轮也曾返回，但响应注明已弃用，所以最终实现使用 v2；两者数值不同不被当成同一来源。

## 失败与范围边界

- Yahoo chart 第一次请求 `AAPL` 即返回 HTTP 429、正文 `Edge: Too Many Requests`；停止该候选，没有轮换域名、伪装浏览器或绕过限制。其他 Yahoo 样本未请求，因此不能宣称 Yahoo 全部证券均不可用。

- 腾讯分钟接口返回 301 到 `web3.ifzq.gtimg.cn`，跟随重定向时 TLS 连接失败；没有将该路径列为可用。
- 成功的腾讯、新浪公共端点属于技术可达性证据；尚未找到明确覆盖本应用个人自动访问方式的授权文本，更不能从公开可访问推导允许多人展示。首版限定本地个人候选，外部版本需另行解决。

## 代码交接

`backend/app/marketdata.py` 提供同步 `MarketDataClient.quote(symbol)`、`intraday(symbol)`、`history(symbol)`、`fx_rates()`；模型为不可变 `Quote`、`Bar`、`FxRate`。价格、汇率、成交量使用 Decimal；时间统一为带时区 UTC。当前支持 60 个内置规则及核验的本地扩展，非法代码直接拒绝，防止把用户输入拼接为任意请求。来源解析、规则注册、港股协议与日线解码已按职责分成独立模块。

错误使用 `MarketDataError.code/detail`，区分 HTTP、网络、解析、未验证能力、缺失数据等；出错不回退到另一种价格或演示数据。httpx2 设置显式连接和读取超时、HTTP/2、连接重试与一兆字节响应上限；HTTP 429 不立即重试。客户端以完整端点 URL 为键缓存响应：报价和分钟线 60 秒，日线及日频汇率 3600 秒；HTTP/网络失败保留 15 秒后允许明确重试。缓存保留首次取得时间，过期后真正收到新响应才刷新取得时间，供应商的市场时间始终不改变。线程锁覆盖缓存未命中的网络调用，八个并发读者只产生一次同端点请求。缓存仅属于当前客户端实例，服务必须复用同一实例；不同端点的首次加载暂时串行，换取当前小样本个人版的简单性。
