# 0.2.0 后端实现与验证

日期：2026-10-23。范围：计划、站内提示、委托快照、复盘、归档分页和导出。本文记录本地候选行为；正式服务部署、真实来源证券扩展和手机交互由对应成员及 PM 汇总，不将受控行情写成真实市场成交。

## 实现与取舍

SQLite 增量增加 `plans`、`plan_alerts`、`plan_monitoring` 三张表。原轮次、订单、流水、笔记和已启用证券表保留。订单新增可选 `plan_id`、`plan_version`、`plan_snapshot`，笔记新增可选 `plan_id`；旧 JSON 缺失字段按未记录读取。旧版请求的幂等比较先按当前模型解析默认值，因此升级后的原请求重试仍返回原订单，不会因新增空字段误报冲突。

计划使用 `draft/active/ended`，普通唯一索引保证同一轮次和证券只有一个进行中计划。编辑提交 `version`，事务内检测旧版本并返回 409。已结束计划不重新激活；通过新计划保留独立判断。归档轮次只读，新轮不复制计划。已经加入自选的观察证券也能记录计划，不会因此取得交易资格；未核验分钟来源时到价判断保持不可用。

下单沿用预览、数量、资金、换汇、费用、T+1、请求幂等和延迟撮合。计划版本、轮次、证券在受理事务内再次核对，保存包含 ID、版本、理由、目标、止损、复盘日期、失效条件及创建修改时间的完整快照。计划后续编辑不改变旧单快照。计划和提示均不产生买卖或撤单。

到期按北京时间日期计算。价格提示保守复用已有完整分钟样本：区间不超过五分钟、正价格和成交量、已核验、证券及币种匹配、来源非空、市场时间和取回时间有效且非未来、市场时间不早于当前二十分钟、区间位于支持的连续交易时段。未来、旧、缺失、零量、停牌标记、午休及来源失败不触价；不从日线高低补造事件。最新缓存样本只要仍满足上述条件即可观察，不要求发生在计划创建之后。提示明确保存实际市场时间和来源，并在消息中保留当时参考阈值与币种，不声称精准触价。

生产 `PlanWorker` 与原 `Worker` 独立运行。计划专用 `MarketDataClient` 拥有独立锁和最多 256 条缓存，防止慢计划请求占住撮合客户端的网络锁。每轮最多处理 16 个活动计划证券，轮询后等待 60 秒；日期提醒先处理，不等待报价。一个来源失败不终止其他标的。普通唯一约束保证每计划版本和条件只生成一次提示，重启、重复响应和已读操作幂等。后台观察状态独立于计划版本；编辑条件后旧观察结果不能覆盖新版本。

复盘按计划展示关联委托及笔记，无计划旧单保留独立条目。成交或到复盘日进入待复盘，记录笔记后进入已复盘；未成交撤单保留“尚无成交/不计作盈利交易”。部分卖出显示剩余关联数量及账户实际持仓，不自动结束计划。汇总收益只来自关联已成交卖单原有 `realized_pnl`，各币种独立；任一卖单缺失收益时总值显示未记录，不用已知部分冒充完整收益。

保留旧五百条轮次详情兼容入口，同时新增订单、笔记、流水的有界完整分页。计划、提示、复盘各自支持分页和独立 CSV，包含归档；原完整流水 CSV 保留。复盘导出包含每笔委托当时快照、实际成交、费用、原币净收益、来源、成交及确认时间，以及带创建时间的笔记。用户文本的前导空白、等号、加减号、`@`、制表符和换行按纯文本防护；负数金额仍保留可计算的数字格式。

## 运行证据

新增 `backend/tests/test_plans.py`、`backend/tests/test_plan_alerts.py`、`backend/tests/test_plan_api.py` 使用临时 SQLite。真实回环 Uvicorn/HTTP 测试验证两个独立登录客户端共享计划、版本冲突、下单快照、关联笔记、提示已读、归档只读、跨轮隔离和导出。

具体通过的行为包括：

- 两线程同时创建同证券活动计划，只有一份成功；旧版本编辑被拒绝；结束后可创建新计划。
- 行情获取期间另一设备修改计划，最终受理事务拒绝旧版本，订单和流水均不增加。
- 计划修改不改变原委托快照；原请求重试仍指向原单；旧字段缺失和旧请求格式可重复重开。
- 买入 200 股、T+1 后卖出 100 股：保留 100 股持仓，计划仍进行中，展示原交易引擎计算的部分已实现净收益；缺失卖单收益不形成完整汇总。
- 未来、过期、缺失、停牌标记、零量、异常区间、异常取回时间、不同证券/币种、非有限价格及非连续交易时段不触价；目标与止损等价边界可触发；北京时间午夜到期正确。
- 应用真实 lifespan 在没有网页请求时生成提示；重复启动不重复生成；日期提示不依赖报价成功；不产生订单和资金变动。
- 慢计划请求实际停留于 `MarketDataClient._load` 的锁内，原 `Worker` 在该请求尚未释放时已经完成委托成交，证明生产两个客户端没有共享此网络锁。
- 活跃证券轮询单次最多 16 项，草稿不获取报价，单个来源失败后其他证券继续；条件修改期间取得的旧结果不写回新版本。
- 507 条订单、507 条历史笔记及流水可逐页完整取得；计划关联订单也可完整遍历；CSV 不受页面 500 条限制，并保留快照与公式防护。

另从 PM 提供的正式旧结构在线备份复制出独立迁移副本，原始备份未修改。副本连续初始化两次后，原六张表的行内容逐项完全一致：`rounds` 1、`requests` 4、`snapshots` 2、`adjustments` 0、`observations` 0、`activated_instruments` 124。SQLite 完整性检查为 `ok`。随后只在副本重开练习，旧现金、持仓、订单、流水、笔记保持一致，原计划留在旧轮，新轮计划为空。私有证据位于 `.omo/evidence/iteration-0.2.0/migration-summary.json` 和独立数据库副本，不进入公有仓库。

## 复现方式

在项目根目录执行后端检查时，应显式进入 `backend`，避免类型检查器从仓库根读取错误配置：

```sh
cd /Users/fuhaotian/Documents/ChatGPT/StockMock/backend
uv run pytest -q
uv run basedpyright
uv run ruff check app tests
uv run ruff format --check app tests
```

浏览器可复现候选夹具已放入 `backend/tests/iteration_server.py`。它只监听回环，使用单独数据库并挂载 `.omo/evidence/iteration-0.2.0/candidate-dist`。控制接口只存在于此测试脚本，不存在于正式应用：

```sh
cd /Users/fuhaotian/Documents/ChatGPT/StockMock
CANDIDATE_PORT=8202 CANDIDATE_DB=.omo/evidence/iteration-0.2.0/ui-test.sqlite3 \
  PYTHONPATH=backend backend/.venv/bin/python backend/tests/iteration_server.py
```

默认合成测试密码为 `iteration-0.2.0-local-only`，可通过 `CANDIDATE_PASSWORD` 覆盖。`POST /_test/advance?minutes=5` 推进时钟并运行实际撮合与提示；`POST /_test/control?price=100&status=valid` 切换样本，状态也支持 `stale/future/suspended/failure`；`POST /_test/history?count=510` 生成明确标记的受控笔记和零金额流水，用于长历史分页。此夹具不读取正式密码或正式数据库。
