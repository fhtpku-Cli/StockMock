## 最小接口说明

后端在实现前产出最小请求/响应示例，前端与独立验证据此并行。沿用精确金额、认证和Origin保护；成功幂等重试先于首次覆盖检查；独立结论表不修改旧持久JSON；归档固定时点只读。

| 接口 | 返回及约定 |
| --- | --- |
| `GET /api/reviews/{subject_type}/{subject_id}?round_id=` | 主体为`plan/order`，有计划订单归计划；返回轮次、只读标记、复盘摘要、完整关联订单、历次结论及一次一致读取的`coverage` |
| `POST /api/reviews/{subject_type}/{subject_id}/conclusions` | 提交`request_id,round_id,conclusion,deviation,next_action,coverage`；覆盖含计划版本、完整已成交ID、已到复盘日和最近结论ID。响应含原结论及重新计算的原轮状态；409保留草稿 |
| `GET /api/reviews/page` | 证券、市场、计划状态、最近记录日及复盘状态筛选；返回`items,total,round_id,read_only,counts,next_cursor,limit`。计数在复盘状态过滤前计算，默认50、最多100；换轮游标409 |
| `GET /api/reviews/{subject_type}/{subject_id}/facts` | 按系统时间/类型/原ID稳定排序，缺确认时间排入未知区；市场时间单独保留。`offset/limit`分页无500条截断 |
| `GET /api/journal/page` | 按笔记日期、证券和市场先筛完整数据再分页；返回已解析关联主体。归属先计划后订单，异常归属为空 |
| `GET /api/reviews/export.csv` | 与工作台同条件选择主体，导出完整子记录及所有正式结论，不受当前页影响；无参数保留全轮及无关联笔记 |

复盘状态为`not_due/pending/reviewed/needs_update`，旧三值`status`将待补充映射为`pending`。工作台`review_state=todo`包含首次与补充待办，归档默认全部。日期按北京时间含开始日和结束日；错误输入或倒序日期422，未登录401，不存在主体404，首次覆盖冲突、归档新写入和同请求异内容409。

## 一次性实机验收

以下步骤在本机部署完成后由本人集中进行。iPhone新交互和Mac整机重启分别记录结果；桌面浏览器仿真与服务重载不能代替这两项。使用原私人入口和已有真实练习记录，无需为验收归档或重置账户。

1. iPhone刷新后进入“资产”，核对同批现金、持仓、应收与总资产；切换持仓筛选，确认占比仍按全账户。轨迹切近7天和自定日期，查看实际记录与缺口，下载并打开快照CSV。
2. 在“现金账户 → 明细与换汇”选择币种、日期、流水类型。查看期初期末与核对差额，下载筛选流水，确认日期控件、中文文件和手机键盘正常；切换类型不应改变全类型期初期末。
3. 打开“复盘”，查看首次待复盘、待补充、已复盘与暂未到期数量；尝试证券、市场、计划状态和最近记录日期筛选，再进入详情后返回，确认筛选保留。普通笔记使用单独的笔记日期条件。导出筛选复盘并在手机打开，主体内保留完整记录。
4. 选择本人确实要复盘的已有计划或旧委托，核对覆盖的计划版本、成交笔数和复盘日期后保存正式结论，确认普通笔记与结论分开显示。以后实际新增成交或改版时，应出现待补充原因；无需特意下测试单。若已有相关提示，点击直达并核对正确计划及原提示背景；查看不自动标为已读。没有提示可跳过此项。
5. 有历史轮次时进入历史，查看同轮计划、结论、资金与轨迹并尝试下载，确认只读；没有历史则跳过。切到后台再返回，切换Wi-Fi/移动网络后刷新，确认仍是同一账户且输入内容可读。记录问题所在页面和操作即可。
