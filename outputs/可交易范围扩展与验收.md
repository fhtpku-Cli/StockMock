# 可交易范围扩展与验收

更新时间：2026-10-23。个人版 `0.1.3` 已部署，正式账户当前可模拟交易 176 只证券。

## 本次要解决的问题

`0.1.2` 已允许在线搜索目录外证券，但新增结果只能观察。内置目录的 60 只证券中只有 52 只可以模拟交易，因此搜索覆盖扩展没有转化为交易覆盖扩展。本次同时提供按需核验启用能力，并在用户现有个人服务中启用一批真实核验通过的 A 股、美股及 ETF。

港股继续只观察。核验失败的证券保留观察和明确原因，不把未知证券或失败的行情静默当作可交易证券，不使用演示价格替代真实数据。

## 产品行为

1. 用户在自选页搜索 A 股或美股，打开目录外证券详情后可选择“启用模拟交易”。已启用证券直接显示交易入口，港股不提供启用入口。
2. 服务确认证券身份、支持的交易规则、至少上市 90 天的存在证据，以及真实报价、日线和完整分钟行情。核验期间防止重复提交，失败可以重试。
3. 成功结果写入当前服务的 SQLite 数据库。详情、自选和搜索结果立即更新；之后的预览、下单、后台撮合、持仓估值与历史查询都使用同一规则。服务重启后继续有效。
4. 可交易数量以实际持久启用成功的结果为准。在线搜索依赖供应商返回，不宣称已下载或完整覆盖全市场；每只新证券仍须满足相同核验条件。

## 规则范围与取舍

| 类别 | 本批处理 |
| --- | --- |
| 成熟 A 股普通主板股票 | 核验后启用，100 股起、100 股递增，普通涨跌幅规则与 T+1；每笔最多 100 万股 |
| 成熟创业板普通股票 | 核验后启用，使用创业板涨跌幅规则和 T+1；限价每笔最多 30 万股，市价最多 15 万股 |
| 成熟科创板普通股票 | 核验后启用，200 股起、1 股递增；不足最低卖出量的余额按对应规则一次卖清；限价每笔最多 10 万股，市价最多 5 万股 |
| 境内普通股票 ETF | 仅启用投资类别和具体涨跌幅规则已核验的证券；每笔最多 100 万份，不以代码前缀猜测跨境、债券、商品或 T+0 属性 |
| 美股普通股票和普通股票 ETF | 核验后启用，常规时段整股模拟，保留既有价格网格、换汇和费用规则 |
| 港股 | 保留真实观察，不启用模拟交易 |
| 风险警示、退市、上市初期、未知类别、未核验特殊代码、杠杆或反向产品 | 不启用，返回明确原因 |

早于当前日期 90 天的真实历史日线可证明证券至少在该日已上市，与原成熟门槛目的相同；该日期不冒充精确 IPO 日期。来源与规则细节另见本批规则来源报告。

## 实现与分工

继续采用单体服务和 SQLite，不增加全市场扫描任务。核验按需执行，有超时与重复请求合并；数据库单行事务和唯一主键保证失败不写入、同一证券不重复启用。扩展目录绑定当前 Engine 实例，不修改进程全局共享目录。

| 所有者 | 责任 |
| --- | --- |
| `tradability_sources` | 身份和规则来源、成熟性与真实行情验证、批量真实探测、来源报告 |
| `tradability_backend` | 启用 API、持久目录、交易与后台全路径、重启和失败行为测试 |
| `tradability_ui` | 启用交互、缓存和详情状态同步、数量说明、移动浏览器验收 |
| 主智能体 | 协调、独立审查、真实集成验证、版本文档、安全部署与 CI 核对 |

## 验收要求

- 使用临时数据库验证启用成功、失败无残留、并发幂等、港股与暂停状态不能绕过，以及完整重建后的目录和后台工作。
- 对主板、创业板、科创板和 ETF 验证数量、涨跌幅、T+1、买卖、换汇、费用及持久化；受控行情只用于可重复行为测试。
- 在真实来源上逐只核验新增候选并记录通过数量。真实 API 请求与受控成交测试分开说明；休市或缺少后续样本时不制造真实成交证据。
- 在桌面和手机尺寸浏览器验证启用成功、失败恢复、重复点击、港股只观察及刷新持久，并回归日期筛选布局。
- 部署前在线备份个人数据库；正式账户只增加证券资格，不写测试交易。部署后核对旧账本完整、实际可交易数量、worker 心跳、本机与私有 HTTPS 入口。
- 推送后核对最新提交对应的 GitHub Actions 总状态确为 `completed/success`，不能用子检查成功代替正式结束。

## 验收记录

### 真实来源核验

124 个新增候选最终全部通过，且与原有 60 只基础目录没有重叠：62 只 A 股、36 只美股、15 只境内股票 ETF、11 只美股股票 ETF。成功规则及逐项行情时间保存在 ignored 的 `.omo/evidence/tradability-sources/`；原始样本不提交。详细依据见[交易范围规则与来源](交易范围规则与来源.md)。

核验期间发现腾讯原 `fqkline` 路径对境内 ETF 返回 HTTP 501，连原有 510300 的日线也受影响。首次切换 ETF 路径后，15 只 ETF 全部重新核验通过；随后正式启用时又发现普通股票旧路径同样失效，独立与精简环境均可复现。最终统一全部境内证券使用同一供应商真实未复权 `kline/kline` 路径。正式浏览器回归又发现港股观察日线同样受该故障影响，因此港股日线一并切换，交易权限和 Futu 适配不变。图表与上市成熟性核验共用 URL 选择逻辑，不使用假数据或复权价格补位。510300、512880 以及四只主板、创业板、科创板样本的收盘、前收盘和原生成交量与独立快照逐项吻合；0700.HK 和 2800.HK 各返回 30 条原始日线，币种、日期、价格与量核对通过。精简环境完整核验恢复；600000 和 510300 在隔离数据库的认证 HTTP 日线与预览通过，恢复验证未下单。

600000.SS 另通过真实 HTTP 启用、报价、预览和限价委托受理，并在重建 Engine 后保留规则与委托。该次发生在闭市，只证明预挂受理；新标的后续成交、卖出与金额变化由受控行情驱动真实 Worker 验证，不冒充真实盘中成交。
