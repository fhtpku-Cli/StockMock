# 0.4.1 后台工具验证

日期：2026-10-24。范围：任务1/2，修改 `scripts/run-service.py`、`scripts/service.py` 和 `scripts/test_service.py`。本记录只声明后台工具候选验证，不代表正式部署、最新完整提交 CI 或本人设备验收；正常恢复服务的 HTTP 与两个业务 worker 另见本版集成验证。

## 实际问题与处理

原有10项服务工具测试通过，但真实隔离根执行 `run-service.py --check-config` 会创建 `paper.sqlite3`。坏 JSON 的失败直接输出第三方异常，未提供安全分类。原始结果保留在 `.omo/evidence/0.4.1/runtime/original-tests.log`、`original-repro.json`、`original-diagnostic.json`。

检查现改为用 SQLite 只读连接在线备份到临时目录，在临时副本运行原有应用构造与全部校验。因此旧库升级、初始轮次以及动态证券资格的读取发生在副本；无库时只初始化临时库。真实启动仍走原数据库与原应用，不改变业务 worker、回环监听、代理信任或单实例规则。临时目录在成功与失败后均自动删除。

诊断路径在第三方依赖、私有配置和密码读取之前建立，固定分类包括日志、配置文件、配置格式、密码文件、密码长度、依赖、应用初始化和服务启动。失败非零退出，终端及日志不打印原始异常、密码、配置正文或私有域名。`install/start`只转达固定类别和中文解释，不转发任意子进程输出。原 plist 内容和归属判定完全保留。

日志仍为单文件1,000,000字节、三个历史文件。目录收紧为0700，现有和新日志为0600；日志目录或文件链接被拒绝，目录不可写时安全非零退出。日志写入自身失败不会由 logging 打印原始记录。Python解释器不存在或系统拒绝执行时不能声称 Python 日志已建立，CLI提示检查解释器和 `status`；自动启动的此类情况需查看系统任务状态。

PM提出锁库挂起风险后，用独占锁真实复现检查超过8秒仍不退出，保存 `locked-original.json`。修复增加SQLite副本读取5秒期限；CLI对子进程检查设置30秒期限。过期仅安全失败，不修改或解除其他进程锁，不增加内部发布门槛。
