# 个人模拟交易首版设计稿

更新日期：2026-10-22。状态：需求讨论已收口，用户已授权 PM 安排子智能体开发与验证。延迟成交与撤单回执、统一模拟费用及简化资金交收已获用户确认。本文保留详细设计依据；未逐项确认的可逆默认值由 PM 按[项目执行计划](./项目执行计划.md)收敛，不再逐项打扰用户。

## 1. 已确认的方向

| 项目 | 已确认要求 |
| --- | --- |
| 用途 | 用虚拟现金练习交易，优先数天到数周的波段，同时兼顾短线 |
| 使用范围 | 首版只供本人使用，后续再开放给朋友 |
| 市场 | A 股、港股、美股和 ETF；具体可交易证券仍须核对数据和规则 |
| 行情 | 尽量免费，接受延迟；尚未同意将盘中交易改成只在盘后处理 |
| 设备 | 电脑、手机共用同一个账户，关闭网页后挂单继续处理 |
| 本金 | 每轮以 100 万元人民币起步，买港美股时自动换汇 |
| 成交与撤单 | 接受延迟回执；等待下单后对应的有效市场价格判断成交，撤单先确认截止之前的成交情况 |
| 模拟费用 | 买入、卖出分别按成交金额的 0.05% 收取，无最低费用；首版不复刻真实市场费税表 |
| 资金交收 | 卖出确认后的净款可再次用于模拟买入，首版简化真实交收及现金账户资金限制 |
| 使用地区 | 主要在中国大陆，没有 iOS 商店上架开发者账号 |
| 当前工作 | PM 统一把控，子智能体开发与验证；暂不公开部署或付费接入 |
| 界面偏好 | 浅色、清爽的资产看板，突出持仓与收益；无必须覆盖的指定证券 |

建议采用自适应网页，提供添加到手机主屏幕的 PWA 入口。持续处理委托需要常驻后端任务，不能依靠手机网页在后台运行。行情尽量免费不代表托管、域名等一定免费；本轮不选择服务商，也不承诺零运行成本。

第一版完成后的目标体验是：在电脑选标的、写下买入理由并挂单；关闭网页后系统继续处理；随后在手机查看成交、持仓和收益；卖出后可以回看当初的理由。

## 2. 建议首版范围

| 能力 | 建议纳入的内容 | 范围边界 |
| --- | --- | --- |
| 个人账户 | 私有登录、跨设备同步、一个活动练习轮次 | 不开放注册、不邀请朋友；数据仍按账户归属保存，方便以后扩展 |
| 搜索与自选 | 按代码、名称、市场和股票/ETF筛选；加入、移除自选 | 搜索得到不等于允许交易；显示“可交易”“仅观察”“暂不可用” |
| 行情详情 | 最新可用价格、报价时间、延迟、市场状态、日线、成交量 | 盘中走势图有数据时再显示；不承诺逐笔、盘口和全部历史长度 |
| 模拟买卖 | 买入、卖出、当日限价单、带价格保护的市价模拟、撤单 | 只用已有现金买入，只卖已有可卖持仓；整笔成交，不模拟排队和部分成交 |
| 资产 | 人民币总资产、可用资金、委托占用、持仓、收益曲线 | 保存人民币/港币/美元账本；不同市场报价时间可能不同 |
| 复盘 | 买卖理由、计划持有期、目标价与止损参考价、成交后总结 | 目标价和止损参考价只作记录，不自动触发买卖 |
| 记录 | 委托、成交、费用、换汇、分红及调整流水；导出 CSV | 记录可追溯；不允许直接改历史成交价或任意补记一笔盈利交易 |
| 重开练习 | 结束当前轮次并保留记录，新轮次恢复 100 万元本金 | 不用随意充值弥补亏损；旧轮次归档前结束全部挂单 |

建议暂缓：融资、做空、衍生品、碎股主动买入、自动止盈止损、长期有效挂单、盘前盘后及集合竞价成交、实时通知、排行榜、跟单、公开持仓和 AI 选股。自动止损尤其容易被延迟和跳空误导，第一版先把计划记录和实际结果做清楚。

资产类别仍按三个市场和 ETF 规划，但可交易清单需逐步验证。建议先支持规则明确、数据稳定的上市股票及普通 ETF；北交所、上市初期、风险警示、退市整理、杠杆/反向 ETF 和复杂公司行动证券先作为待支持项，不把它们默认为已经覆盖。“主流标的覆盖”不等于一次性做全市场实时扫描。

## 3. 页面结构和操作路径

电脑使用左侧导航，手机使用底部四个入口：**资产、自选、委托、复盘**。账户设置放在头像入口。标的详情和下单面板由上述页面进入，不再增加常驻导航。

| 页面 | 从上到下的主要内容 | 主要操作 |
| --- | --- | --- |
| 资产，默认首页 | 总资产与累计收益 → 可用资金和委托占用 → 收益曲线 → 持仓列表 → 待处理委托摘要 | 看仓位；进入持仓详情；卖出；查看现金明细 |
| 自选 | 搜索 → 市场/类别筛选 → 自选列表 → 行情更新时间 | 搜索标的、加入自选、打开详情 |
| 标的详情 | 名称/代码/市场/币种 → 价格、市场时间和延迟 → 日线 → 交易规则摘要 → 本人持仓与计划 | 买入、卖出、编辑计划、查看历史交易 |
| 下单面板 | 买卖方向 → 委托类型 → 限价/价格保护 → 数量 → 资金与费用预估 → 可选理由 → 提交 | 按数量或可用资金比例下单；查看预计占用人民币 |
| 委托 | 待处理/已结束切换 → 状态、理由和可操作项 → 成交详情 | 撤单、重新下单、查看成交依据和流水 |
| 复盘 | 已结束持仓周期/交易记录 → 原计划与实际买卖 → 净收益和费用 → 复盘笔记 | 筛选市场与日期、写总结、导出 |
| 账户设置 | 当前轮次、规则说明、现金币种、导出、历史轮次、登录管理 | 外币换回人民币、重开练习、查看归档 |

持仓列表默认显示名称、数量、可卖数量、成本价、现价、市值、盈亏及仓位；手机先显示名称、盈亏和仓位，点开查看其余信息。人民币折算用于汇总，订单输入和证券价格使用交易币种，避免误把“100 美元”理解为“100 元”。

首次使用只需完成私有登录、查看初始资金和模拟规则，不要求填写真实券商账户。下单默认选限价单；快捷仓位按钮按可用资金、费用和合法数量向下取整，不悄悄超出预算。每次提交都有费用、换汇、委托有效期和等待说明，不只在首次引导里提示一次。

建议展示的订单文案：

> 当前显示的是 09:45 的市场价格，数据约延迟 15 分钟。你在 10:00 提交的委托，需要等 10:00 之后的有效行情到达再判断成交。预计 10:15 以后开始确认，实际以数据到达为准。

提交成功显示“委托已受理”，只有成交后才显示“买入成功”。手机断网时可查看有时间标记的缓存，不能把本地保存的操作显示成已受理委托。

## 4. 行情与模拟成交

### 4.1 已确认的成交方向与细化规则

已确认采用**等待下单后对应的有效市场价格抵达，再判断模拟成交**的方向，并接受成交及撤单回执延迟。以下采样频率、价格保护、超时阈值等仍是细化建议。这个模型适合练习波段方向、仓位和执行纪律；不还原真实盘口的排队、成交深度和市场冲击，也可能漏掉两次采样之间短暂触及的价格。

价格样本必须带有该价格对应的市场时间。服务器获取时间、页面刷新时间不能替代市场时间。首版优先验证带明确成交时间的价格快照；如果某来源只能提供 K 线，只使用完整且非空的区间收盘价，区间起点不得早于订单生效时间，不用高低点猜测是否成交。每个标的固定采用一种已验证的样本口径，在成交详情中可查。

2026-10-28用户确认0.4.4采用“当时有效观察版本”：完整区间表示对应五分钟市场时段已经结束，不代表供应商已收齐所有迟到成交或以后不会修订。每笔订单按首次成功处理该区间的版本判断；即使当时未满足限价，后续同标签修订也不重新尝试。成交后保留当次来源、区间、真实取得时刻与采用价量，后续修订不改历史账本，因此可能与后来查看的历史图表不同。取消固定17分钟等定稿等待，仍保留未来标签、未结束区间、下单生效前区间及过旧新单行情的拒绝条件。详细边界以[0.4.4计划D1](0.4.4迭代计划.md)为准，新方案须完成本版验收和正式切换后才生效。

有挂单的标的建议每 60 秒尝试获取一次样本；自选在打开页面时按需刷新，持仓低频估值。这是请求调度目标，不代表供应商每分钟都有新数据。若额度不够，要明确降低频率或缩小活动标的数量，不把静默漏采说成连续行情。

一笔成交须满足：

1. 行情属于同一证券、同一币种、同一指定来源，使用未复权价格。
2. 对于时间点报价，价格对应的市场时间严格晚于服务器受理时间，且处于订单已生效的交易时段；时间精度不足时保守跳过边界样本。
3. 如果存在撤单或到期截止，本应用使用的区间样本必须完整落在生效至截止闭区间内，区间结束时刻可以等于截止；时点报价的严格早于规则见§4.3，不用于排除恰好结束于截止的完整区间。
4. 市场状态、价格和数量有效，有足够的已预留资金或可卖持仓；新单参考行情仍受20分钟时效保护，恢复后撮合未处理历史区间按§4.4判断，不因确认晚于20分钟直接跳过。
5. 每次只处理新增的有效样本。重复数据不能再次触发成交，已处理时间以前的迟到数据不能推翻已结束的订单。

成交记录同时保留下单时间、价格对应市场时间、系统确认时间和样本来源；0.4.4新成交还保存实际采用的完整行情依据，旧记录未保存的字段明确显示缺失，不事后补造。“成交时间”展示市场时间，“确认时间”另列；现金与持仓在系统确认之后才变成可用，不能让用户提前使用尚未确认的卖出款。新单参考价、计划到价提示、独立报价估值各按原职责和时效处理，不宣称全部页面共享同一观察版本。

### 4.2 两种委托

| 项目 | 限价单，建议默认 | 市价模拟，带保护 |
| --- | --- | --- |
| 价格 | 用户填写最高买价或最低卖价 | 下单前显示参考价及允许的最高买价/最低卖价 |
| 判断 | 买入样本价不高于限价；卖出样本价不低于限价 | 用下单后首条符合时间与数据要求的样本，检查交易限制与保护价，一次决定成交或终止 |
| 成交价 | 满足条件时按样本价，允许优于限价 | 按样本价 |
| 价格保护 | 限价本身就是价格边界 | 建议参考价上下 2%，按证券报价单位保守取整；这是本产品规则，不是交易所统一规则 |
| 超出价格边界 | 继续等待后续样本，直到撤单或到期 | 终止并显示“价格超出保护范围”，不转成长期等待单 |
| 受理时段 | 可在休市时预挂，到下一支持时段生效 | 只在支持的常规连续交易时段受理 |
| 资源预留 | 买入占用数量×限价及预估费用；卖出占用可卖数量 | 买入按保护上限及费用预留；卖出占用可卖数量 |

首版建议不额外添加固定滑点，费用单独计收。原因是免费样本缺少买卖盘口，随意加一个精确数字不能证明更接近真实成交。结果说明中明确采用采样价与整笔成交；后续若增加滑点模型，必须重新检查限价和资金，不得使成交价突破用户限价。

委托主状态建议只有“已受理、撤单待确认、已成交、已撤单、已到期、已终止”；等待开市、等待延迟数据、价格未满足、行情异常作为“已受理”下的具体原因展示。请求未通过校验称“受理失败”，与已受理后终止分开。撤单待确认期间不再允许修改原委托；第一版改单采用确认撤单后重新下单。

提交前资源不足则拒绝受理；成交前再核对一次。不得产生负现金、负持仓，也不擅自缩小用户委托数量。多笔订单及两个设备共享同一份可用资金，不能各自按全部现金下单。

### 4.3 有效期、休市与撤单

建议首版只提供当日有效。常规时段提交的限价单在该交易日最后一个支持时段结束时截止；午休挂单可在当日下午继续；收盘后、周末或节假日提交的限价单，到下一个交易日生效并于该日截止。页面明确写出有效交易日。后台按交易所日历和当地时区处理，美股不得用全年固定的北京时间排表。

集合竞价、盘前盘后、特殊交易时段首版不参与撮合，界面标为“该时段仅可预挂限价单”。本应用的可执行时段应单独列明，不把它称为交易所全部交易时段。

撤单需要区分两种情况：

- 尚未生效的预挂单，且此前没有可成交区间，可以直接撤销并释放预留。
- 已生效的订单，撤单先显示“撤单待确认”，记录服务器收到撤单的时刻作为截止。继续处理完整落在生效至截止区间内的有效样本；如果它们已满足成交条件，则显示已成交及撤单未生效的原因。0.4.4确认规则为：截止后没有候选完整区间、最后候选区间已处理而未成交，或有效同源样本的市场时间已推进过截止时，确认已撤单并释放预留。否则继续等待或按下述数据不足规则终止。

当日到期也使用同样的截止处理：收盘后仍可能收到收盘前的延迟样本，所以不能到钟点立即释放所有资金。撤单与到期采用较早的截止。时点报价恰好等于截止时不成交；本应用使用的区间样本按2026-10-28用户决定，完整落在闭区间 `[生效, 截止]` 内即可参与成交，包括结束时刻恰好等于截止。美股正常或提前收盘的最后五分钟因此可以成交；A股14:55–15:00跨过14:57截止仍不能成交。详见[0.4.4计划D2](0.4.4迭代计划.md)。

这里的确认仅针对本系统实际采集的样本，不表示掌握了全部市场成交。对价格快照，数据时间推进不保证中间每次成交都已取得；产品不宣称撤单结果等同真实券商。

### 4.4 行情中断与终止规则

每个已接入来源需要记录其预期延迟与采样间隔。建议以“预期延迟之外再多 5 分钟”作为首版异常容忍值；数值需在后续真实采样后复核，不作为供应商时效保证。

交易时段内超过容忍值没有新的有效样本，暂停该标的新订单，现有订单显示“行情异常，暂缓判断”；保留最后报价用于带时间标记的估值，不能拿它持续成交。休市和已知停牌不按普通网络超时处理。

0.4.4将数据不足终止细化为：已到撤单或到期截止，且超过最后候选区间结束20分钟仍缺少确认依据时，仅在本轮行情请求成功，或该证券持续请求失败满20分钟时终止并释放预留。原因写“数据不足，未确认成交”，不写“确定未曾触价”。已结束订单不再接受迟到数据回填；不凭缺失区间的日线高低点补成交。

后台重启或休眠后恢复时，订单尚未结束，且来源实际返回同源、已结束且时间语义有效、尚未处理并完整落在生效至截止内的区间，仍按市场时间判断成交，即使取得或处理时间已晚于截止或该区间20分钟。按本单恢复后首次成功处理的版本决定，取得时间如实记录恢复后的时刻，不假称停机时已经取得，也不补造当时未保存的版本。订单参数不因后见行情改变，成交时间记录区间市场时间、确认时间记录实际处理时间，超过20分钟时解释“后台延迟处理”；此前申请撤单但有效区间已满足条件时说明“撤单未生效”。服务启动、请求成功或相邻tick间隔超过5分钟时清空连续失败计时，避免刚恢复网络的一次失败直接终止。新单、估值和计划到价提示的20分钟时效不变，详见[0.4.4计划D3–D4](0.4.4迭代计划.md)。所谓“关网页继续处理”指后端仍运行时；来源缺失期间不制造成交，服务停机必须让用户看到异常影响。

首版不在挂单期间悄悄切换数据源。确需切换时，先暂停并结束受影响挂单，再恢复新来源的交易，避免使用两个来源不同时间口径拼接成交。

### 4.5 三个可直接评审的例子

下列数字均为说明规则的假设，假设来源恰好延迟 15 分钟，不代表实际数据保证。

| 场景 | 时间与价格 | 预期结果 |

## 5. 各市场规则与简化边界

| 维度 | 首版规则及建议，已确认事项单独标注 |
| --- | --- |
| A 股可卖数量 | 当日买入普通 A 股的数量，到下一个该市场交易日才转为可卖；按实际模拟成交所属交易日计算，不按收到回执的自然日计算 |
| A 股数量 | 按板块和证券规则校验，不能把全部 A 股统一写死为 100 股；科创板另有最低数量要求 |
| 境内 ETF | 按具体产品确认能否当日卖出，不能把所有 ETF 当作同一种 T+0 或 T+1 规则 |
| 港股数量 | 按每只证券当时的每手股数，普通买卖只用整手；因公司行动形成的零碎份额进入单独核对，不假装普通整手价可直接清算 |
| 美股数量 | 首版按整数股买卖，暂不支持券商碎股交易 |
| 港美股当日卖出 | 模型允许已确认买入的持仓当天卖出；这是首版模拟选择，不代表完整复刻现金账户的资金限制 |
| 资金交收，已确认 | 卖出确认后的净款可立即用于下一笔模拟买入；首版不还原各市场真实交收、提现或现金账户违规限制，规则页标注“资金交收简化” |
| 涨跌停与停牌 | 使用证券自身已核验的限制；已知停牌时不受理新单，既有限价单等待复牌或到期。没有盘口时，买入样本恰处涨停、卖出样本恰处跌停，保守地不执行；限价单继续等待，市价模拟终止并说明原因 |
| 申报细节 | 校验合法数量、价格步长和已支持的日价格边界；暂不复刻所有盘口相关的动态申报范围、竞价规则或券商权限 |

普通 A 股与部分 ETF 的回转差异，可见[上交所交易规则与附件](https://www.sse.com.cn/lawandrules/sselawsrules2025/fund/trading/c/c_20260424_10817739.shtml)及[深交所 2026 年交易规则](https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020260424690713155663.pdf)。上交所附件同时单列科创板数量规则。因此可卖数量、最小数量、数量递增单位必须按证券维护。

港交所于 2026 年公布分阶段调整每手股数框架，仍需查具体证券，不能把某一个每手股数当作全部港股的统一值；该公告的适用范围也不等于全部 ETF。见[港交所公告](https://www.hkex.com.hk/News/Market-Communications/2026/260630news?sc_lang=en)。

美国标准 T+1 指交收周期，不能直接理解为“今天买的股票明天才能卖”。本产品先简化资金交收，不能用于训练真实现金账户的全部合规约束。见 [SEC 投资者交收说明](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-bulletins/new-t1-settlement-cycle-what-investors-need-know-investor-bulletin)。以上是有针对性的规则核验，尚不是全部证券规则验收。

## 6. 资金、换汇与收益口径

### 6.1 自动换汇

用户只投入一笔 100 万元人民币虚拟本金；账本保留人民币、港币、美元三个现金余额，外币初始为零。

建议买入时优先使用同币种可用现金，不够的部分自动用人民币兑换。下单预览展示换汇金额、参考汇率及其时间；受理时锁定本单的参考汇率并预留人民币，真正成交时才记录兑换与买入，未成交的部分不发生换汇。这是简化的虚拟换汇规则，不模拟银行或券商保证汇率。

首版只用当日有效单，锁定汇率只用于该订单的有效期。估值继续使用最近有效汇率，不能用订单锁定汇率覆盖全部持仓估值。汇率来源、币种覆盖和发布时间仍需后续验证，不能把尚未接入的汇率说成已经可用；建议日频更新足以支撑当前波段用途。

卖出港美股后净款先留在港币/美元余额，下次同币种买入优先复用。账户页提供“换回人民币”；不自动跨美元与港币兑换，人民币不足时提示用户先处理可用外币。全部转换均记录金额、汇率和时间，换汇本身不算新入金或交易盈利。

首版建议不另收虚拟换汇费。缺少有效汇率时，不受理需要自动换汇的新订单；已有同币种现金且其他条件满足的订单可以继续。总资产保留最后可用汇率并标记估值时间；超过预期发布时间仍未更新时显示“汇率待更新”。

### 6.2 费用

已确认首版采用以下教学参数：**每次买卖按成交金额的 0.05% 收取模拟费用，无最低费用**。例如买入成交额 10 万元，费用 50 元；卖出时再按卖出金额计收。

这不是 A 股、港股或美股的真实费税表，不能宣传为真实券商净收益；第一版也不另叠加未核实的印花税、平台费等。费用参数在每轮开始时确定，后续若改用真实费用模式，开新轮次应用，不重写旧成交。

买入费用计入持仓成本，卖出费用从卖出收入中扣除。每笔成交在交易币种下按最小货币单位计算并统一四舍五入。价格与数量使用证券规定精度，资金预留向上留足，避免四舍五入后超用资金。

### 6.3 资产和复盘

总资产按“各币种现金＋持仓市值＋已确认应收分红”折算人民币。委托占用的现金仍属于资产，不得重复加总或从总资产中扣掉。仅估值汇率变化不产生真实换汇流水。

首版没有中途入金、出金，累计收益可直接定义为“总资产减 100 万元”，累计收益率为该差额除以 100 万元。持仓按移动加权平均成本计算，买入费用计入成本，部分卖出结转对应平均成本；归零后再次买入视为新的持仓周期。卖出所得只包含已卖份额的已实现盈亏，剩余份额仍计算未实现盈亏。

交易详情显示原币收益；资产首页显示人民币总收益。不能把原币股票涨幅直接称为账户收益率。首版可先不做复杂的价格/汇率收益归因图，但必须同时保留成交时汇率和当前估值汇率，并说明人民币收益包含汇率影响。

收益曲线按北京时间每天 00:00 的已确认账本及当时最新可用价格、汇率生成快照；它是账户观察时点，不是所有市场共同收盘时点。尚未确认的延迟成交在确认后入账，不倒填可用资金。首页先强调累计收益；个股“今日涨跌”按其市场口径单独显示，避免与账户日收益混淆。缺报价时保留上次估值并标记，不能按零元估值。

复盘首版聚焦“原计划、实际操作、费用、结果和笔记”。胜率、年化收益、风险调整收益等统计暂缓，避免对少量交易和不同持仓周期产生误导。

### 6.4 分红与拆股不能直接忽略

波段持仓也可能跨过除息或拆股。建议支持有可靠数据的现金分红与拆股；不把供应商提供复权图表等同于已经处理账户收益。

- 现金分红：依据确认的权益规则和持仓记录建立应收，支付日再转为可用现金，避免除息后资产无故减少；首版按税前金额模拟，规则页标注不模拟个税与预扣税。
- 拆股、合股：在生效时调整数量及单位成本，总成本保持一致；相关挂单以生效时点为截止结束，先处理此前有效区间的延迟样本，再应用公司行动，提示用户按调整后的价格和数量重下。资料不足以确认先后时暂停核对，不混用新数量与旧价格。
- 图表和成交默认使用未复权价；若增加复权图表，必须显式标记，不能把复权价格用来记账并再重复派息。
- 数据缺失、非整数份额或复杂公司行动：该持仓显示“收益待核对”，暂停相关交易；个人版可依据公开凭证新增一条带理由的调整流水，不直接覆盖旧记录。更正后的资产快照标记已修正。

完整的公司行动自动化取决于数据实际质量。如果免费来源不能支撑，需明确接受个人核对流程，不能交付一个跨分红后收益明显错误却仍显示确定收益的版本。

## 7. 后端职责与后续扩展

建议保留一个应用后端、一套数据库和后台任务，不拆成多个服务。后端负责受理委托、预留资源、同步行情、模拟成交与记账；两个设备读取同一份账户状态。定时处理不依赖用户是否打开网页，也不使用仅在访问时唤醒且无法持续执行的托管方式充当持续撮合能力。

首版只有个人私有入口，但用户、账户和练习轮次分别记录归属。后续朋友加入时再增加邀请和多账户界面；不提前做完整社交系统。成交、持仓、现金和换汇同一事务更新，使用普通主键、唯一约束与重复请求识别防止重复记账。

来源选择延续[免费行情数据源调研](./免费行情数据源调研.md)：Yahoo/yfinance 是跨市场个人候选，BaoStock 可补 A 股历史，美股可另评估 Alpaca；尚无接口接入验收。数据的个人用途、服务端访问条件和大陆可用性仍要实际验证，不能因“个人版”就推定所有自动获取方式都获准。

后续开放朋友版前，再确认多人数据使用条件、账户隔离和调用预算；这些不作为当前设计讨论的前置审批。免费数据若无法提供可靠的市场时间，相关证券先仅观察，不用 EOD 自动替代盘中成交。

## 8. 后续如何判断首版可用

以下为设计验收场景，尚未运行开发测试。

| 场景 | 应看到的结果 |
| --- | --- |
| 电脑挂单后关闭页面，手机再进入 | 后端持续处理；两端看到一致的订单、资金与持仓 |
| 显示旧报价时提交订单 | 不立即按旧价成交；出现等待原因和对应时间 |
| 限价单遇到较好或较差样本 | 只在价格满足边界时成交；买入不超限价、卖出不低于限价 |
| 市价模拟发生跳空 | 超过保护范围时终止，现金不透支，不自动改成另一种订单 |
| 撤单与延迟成交发生先后冲突 | 按价格市场时间与撤单截止解释结果；确认前不能重复使用占用资金 |
| 下单、撤单与行情响应重复 | 只形成一笔对应记账；两台设备不会各自花掉同一笔现金 |
| 不同市场、ETF与节假日 | 可卖数量、整手数量、有效交易日按证券规则处理 |
| 外币余额不足时买入，再撤单 | 人民币被正确预留；未成交部分无换汇，结束后完整释放 |
| 卖出港美股后再次买入 | 优先使用留下的同币种现金；人民币总资产与流水可对账 |
| 收盘后才收到收盘前样本 | 按订单截止处理，不能刚到收盘就错误确认撤单或释放预留 |
| 行情中断或后台停机 | 明示影响；不编造缺失区间成交，不回填已终止订单 |
| 分红、拆股或数据更正 | 资产无重复计入；不支持的事件进入待核对，调整记录有依据 |
| 结束一轮并重新开始 | 未完成订单先结束；旧轮次只读保存；新轮次为 100 万元 |

当前判断：**需求已收口，开发与验证已启动。** 用户已明确委托主智能体作为 PM，安排子智能体执行。个人使用顺序、设备方式、本金、延迟成交与撤单回执、0.05% 模拟费率、简化资金交收与浅色资产看板已确认；剩余可逆细节由 PM 决定，见[项目执行计划](./项目执行计划.md)。具体行情能力必须以真实请求和连续采样证据为准，不把本地受控测试说成真实市场验收。正式上线及新增付费另行处理。
