# 持仓练习前端

React、TypeScript、Vite 与 Bun 构建的个人模拟投资界面，当前版本为0.4.7。四个主入口为资产、自选、委托、复盘；证券详情、交易预览、现金换汇和轮次归档在二级面板中完成。账户与行情来自本地后端，来源失败不替换为演示数据。产品交付证据见[0.4.7执行记录](../outputs/0.4.7执行与验收记录.md)，界面约定见[DESIGN.md](DESIGN.md)。

## 新安装与已有正式服务

2026-10-30用户验收后，R01–R03前后端已成套部署，版本仍为0.4.7。活动委托显示服务端等待原因和完整北京时间；跨预览截止提交会拒绝、保留草稿并说明新旧有效期，必须重新预览。旧服务不支持新请求字段，部署与回退均须前后端配套。128项前端测试/281断言及独立临时构建通过，部署与正式只读验收见[R01–R03记录](../R01-R03修复与验证.md)。

以下命令适用于尚未运行正式服务的新安装，从项目根目录执行：

```bash
cd frontend
bun install --frozen-lockfile
bun run build
cd ..
./scripts/start-local.sh
```

浏览器打开`http://127.0.0.1:8000`。首次启动会交互设置私有密码；需要改密时，先正常停止已有实例，再执行`./scripts/start-local.sh --set-password`，不要打印或提交密码。前台进程必须保持运行才能处理委托。已安装LaunchAgent的个人主机沿用[常驻方案](../outputs/个人访问与常驻方案.md)，无需重新安装或启动第二个实例。

已有正式服务时，`frontend/dist`就是正在提供给用户的页面。开发验证应使用下节的独立输出目录，不能用普通`bun run build`提前覆盖正式页面。`bun run dev`和`bun run preview`的默认API代理均指向8000；切换前端端口不会隔离账户。需要写业务数据的界面测试必须同时使用隔离后端、临时数据库及测试凭据。

## 常用本地验证

从项目根目录执行，输出目录每轮使用一个新名称，避免覆盖历史验收包：

```bash
bun run --cwd frontend test
bun run --cwd frontend build --outDir ../.omo/evidence/local-check/candidate-dist
```

`test`执行`tests/*.test.ts`；0.4.7交付时为113项测试、255个断言，覆盖精度、结构解析、市场时段及查询竞态等行为。构建命令包含TypeScript检查。数量属于该版实际交付记录，本次文档维护没有把历史测试计数冒充新跑结果。按改动范围另执行Biome及相关真实浏览器场景；构建通过不等于完整体验验收。

## 浏览器脚本的适用范围

仓库保留了早期版本的脚本和受控服务，它们不是一条可直接对正式账户执行的通用验收命令。运行前需核对当前界面、数据夹具、静态包和证据目录；本次没有重新认证这些旧矩阵可在0.4.7完整通过。

| 入口 | 实际目标、凭据和写入边界 |
| --- | --- |
| `tests/smoke.mjs`、`tests/interactions.mjs`（`test:browser`） | 默认8000，可用`FRONTEND_TEST_URL`指定地址；读取本机`.local-password`。交互脚本会增删自选、保存笔记，必须对临时测试账户运行，不能直接在正式服务执行`test:browser` |
| `tests/live-order.mjs` | 同上使用默认8000与本机密码，会提交并撤销委托；非交易时段限制不能使正式账本写入变成安全的只读检查 |
| `tests/price-precision.mjs`、`tests/personal-live.mjs` | 读取真实页面和API，默认8000，可设`FRONTEND_TEST_URL`；使用本机密码。历史只读检查不证明本轮正式环境已重新验收 |
| `tests/controlled_server.py`＋`tests/trading.mjs` | 固定8001、临时SQLite、受控行情，读取本机密码；`test:trading`固定8001，不受`FRONTEND_TEST_URL`覆盖。服务默认使用已有`frontend/dist`，不会自动挂载新候选包 |
| `tests/personal_server.py`＋`tests/personal.mjs` | 固定8002、临时SQLite、种子持仓及2026-10-22受控时钟；同样读取本机密码和已有静态包，停止服务后清理临时库 |
| `tests/tradability.mjs` | 独立5197/8027、随机测试口令和临时库；要求`.omo/evidence/tradability-ui/site`中的候选包，包含真实启用流程和明确受控的外部来源 |
| `tests/iteration-ui.mjs` | 0.2.0历史矩阵，调用`backend/tests/iteration_server.py`，使用8202及历史候选目录；数据库/输出路径有历史固定值，不能原样重跑覆盖原证据 |

常用浏览器助手优先使用`CHROME_PATH`，其次使用macOS系统Chrome，否则用已安装的Playwright Chromium。不同矩阵可能另用WebKit，应先读对应脚本。截图和私有响应留在Git忽略的`.omo/evidence/`或`work/`，不进入公有仓库。需要重新验证旧矩阵时，先适配独立新目录和当前接口；不能通过改掉安全断言让旧脚本变绿。

本版完整浏览器范围、受控时钟、真实请求及正式只读验收分别记录在[0.4.7计划](../outputs/0.4.7迭代计划.md)和[执行记录](../outputs/0.4.7执行与验收记录.md)。私有辅助工具不是新克隆仓库自带的测试依赖。

## 当前功能与维护约定

A股与美股在线搜索结果可在详情申请启用模拟交易；成功核验后才更新资格，失败保留观察原因，港股不提供启用入口。科创板显示200股起、1股递增；数量、资金、费用、T+1与成交判断均由后端负责。

复盘自0.4.0起区分首次待办、待补充、已复盘、暂未到期；普通笔记不代表完成，正式结论按覆盖事实判断。归档只读，计划、订单、笔记、流水和结论按各自接口完整分页及导出。资产快照自0.4.5起允许当天当前轮的不完整记录恢复为首次完整观察并保留首次失败信息，完整记录与历史日不重算。

0.4.6补齐活动委托摘要、下一批可卖时间及换轮查询保护；0.4.7在详情独立显示市场时段，报价失败不遮蔽时段，时段失败也不新增交易禁用条件。时段、报价和订单受理是不同判断，不能用展示状态代替下单校验。

- `src/schema.ts`及各领域schema检查外部结构；`src/api.ts`统一请求、错误与格式。资金显示两位，证券价格按最小价位显示，汇率显示六位；不在浏览器重算资金。
- `src/MarketSession.tsx`及对应查询、schema文件负责市场时段；`src/Detail.tsx`负责详情组合。资产摘要、持仓限制和复盘沿用现有组件，不扩展全站状态框架。
- `src/styles/`按基础、布局、组件与响应式拆分，修改后检查相关文件。批量格式化会写入文件，按需选择范围，不作为文档检查步骤。
- PWA只提供安装元数据，不缓存账户或离线提交交易。本人iPhone基础四项和Duo已通过，Mac整机重启继续后置；不重复要求历史全套实机测试，具体边界见[实机记录](../outputs/iPhone实机验收记录.md)。
